## 0. 目标(一句话)

**让一场真实会话在报告里对上号** —— 现在对不上,所以报告恒为「本次观测覆盖 0 / 20」。

**成功的定义(一条,可执行)**:在**前端**跑一场真会话(录音 + 收帧)→ 生成的报告里 `本次观测覆盖` **不是 0**,且报告头点名的来源**就是那一场的 `session_id`。**

## 1. 范围

**在范围内**

1. **读侧按 `session_id` 选日志** —— 替代现在的"每模态按文件名时间戳取最新"(`report_frontend/data_loader.py:104-129`)
2. **报告生成接受并真的使用 `session_id`** —— `generate_report(session_id=None)` 现在**收下就丢**(`report_generator.py:40`)
3. **前端改用服务端铸的号** —— 现在前端自己造 UUID(见 §3.2)
4. **披露补齐** —— 选了但**读不出来**的模态必须显示成「未读到数据」,不许静默消失(§3.3)

**不在范围内(明确记下,别顺手扩)**

- **VIDEO 模式等价性门**、**M3 阈值重登记** —— 各自单列(已在 `docs/下一步.md` §3 第 15/16 条)
- **哨兵值歧义**(语音能量 50.0、抖动 0.0、专注度只有三档)—— 另一个问题,单列
- **前端那几个无产出方的字段**(如"语音流畅度")与"一直显示在录音"的状态机 —— 前端独立问题
- **`refresh_manifest` 的真消费者** —— 见 §8 第 1 条,**本轮刻意不做**,理由在那里
- `examples/*`、`visualization.py` 的清理(承 M1.5 的 deferred)

## 2. 决策记录

| # | 决策 | 依据 |
|---|---|---|
| **D1** | `session_id` 契约**以服务端铸号为唯一来源**;前端不再自造 UUID | §3.2 实测:两套 id 并存是"对上号"不可能成立的根因。三条候选(a 前端采用铸号 / b 放宽加载器正则 / c 服务端 409)里选 **a** —— b 会让两套 id 长期共存,恰好削弱"按 id 归堆"这条 M2 存在的理由;c 在单会话下无收益、且会连带要求前端同步改,**a 是 c 的前置** |
| **D2** | 报告**接受显式 `session_id`**;不给时退到"最新的一场",并在报告头**写明是哪一场** | 现在"收下就丢"等于无法指定;而"最新一场"作为缺省仍要**说清**,否则读者仍不知道看的是谁 |
| **D3** | 加载器**不再猜** —— 目标 `session_id` 定了之后,每个模态只找**该 id** 的那份文件 | 现在的"每模态取最新"是把不同场次拼起来的直接机制 |
| **D4** | 披露**必须**覆盖"选了但读不出来"的模态 | §3.3:I4 的实现让消失的模态**静默缺席**,报告却说"以上模态来自同一场会话" |
| **D5** | 本轮**不做** 409 归属契约 | 单会话下不会触发;且它是 D1 之后才谈得上的事(见 §8 第 2 条) |

## 3. 实测事实(2026-09-24 真实前端使用,是设计的地基)

### 3.1 报告恒为 0/20

同一批报告(`data/output/Research_Assessment_Report_2026*.html`)全部显示
`覆盖 0 / 20`、「未采集到」×17。加载器实测选了**三场不同会话**:

```
面部   <- 20260924_221811_9212   ┐ 同一场
手势   <- 20260924_221811_9212   ┘
语音   <- 20260924_223315_5980   ← 另一场,且日志只有表头(292 B,空)
研究语音 <- 20260924_132055        ← 今天下午那场
```

空的那份把有数据的那份压掉了(按文件名时间戳取最新)→ 语音读不出来 →
连接词密度进不了特征引擎 → 20 个槽全缺证据。

### 3.2 前端自己造了一套 id(根因)

`~/JingXin-frontend/src/services/api.ts:9-23` —— 模块级 IIFE,从 localStorage 取,
没有就 `crypto.randomUUID()`,然后:

- `faceApi` / `gestureApi` 用这个 **UUID**(`:40` / `:65`)
- `voiceApi.interview.start()` 打 `/interview/start` **不带 id**(`:98`),服务端**另铸一个号**,
  而它返回的 `session_id` **前端拿到就丢**

**两套 id 永不相等** ⇒ face/gesture 日志以 UUID 命名、语音日志以铸号命名 ⇒ 报告端
**在任何情况下都拼不成一场**。

**加载器正则实测**:
```
face_au_log_70efe7e5-8bff-417e-902e-b4d27aa3cfcd.csv   正则匹配: False   ← UUID,永远看不见
face_au_log_20260924_221811_9212.csv                   正则匹配: True
```

### 3.3 I4 的披露有个缺口

报告头实际写的是:

> 数据来源:面部 · 20260924_221811_9212;手势 · 20260924_221811_9212。**以上模态来自同一场会话。**

**语音整个消失了,而"同一场会话"读起来像是一切正常。** 原因是 I4 的实现
(`data_loader.py` 的 `selected_sessions`)**只记真正读出来的模态** —— 当时的理由是
"声称用了没有数据的模态比不说更坏",但后果是**静默省略**,读者无从察觉。

## 4. 组件与改动面

| 文件 | 改什么 |
|---|---|
| `report_frontend/data_loader.py:104-129` | 选择规则:先定**目标 `session_id`**,再按 id 取每个模态的文件;**不再按时间戳跨场次取最新** |
| `report_frontend/data_loader.py` 的 `selected_sessions` | 值从"模态→sid"扩成"模态→(sid, 状态)",状态含**未读到数据** |
| `report_frontend/report_generator.py:40` | `generate_report(session_id=...)` **真的用它**;缺省取"最新一场"并写明 |
| `report_frontend/report_generator.py` 的 `sources_disclosure` | 渲染未读到的模态 |
| `app.py`(Flask 面板,:5000) | **报告是从这里生成的,不是前端直接调 `report_generator`** —— `/api/report/structured`(`app.py:183`)内联跑 loader→engine→mapper;`/api/run/report`(`:99`)去跑 `report_frontend.report_generator` 的 `__main__`。两处都要能带上并透传 `session_id`。⚠️ 顺带:`module_map["voice"]`(`app.py:113`)指向一个**不存在的模块**(真文件在 `voice_interaction/examples/`),是既有缺陷 —— 本轮**只做不改**,除非它挡住验收 |
| `~/JingXin-frontend/src/services/api.ts:9-23` | `SESSION_ID` 从"模块级 const + 自造 UUID"改成**可写、由 `interview.start()` 的返回值填充** |
| `~/JingXin-frontend/src/services/api.ts:98` | `interview.start()` 保存并广播服务端返回的 `session_id` |
| 前端调用方(AssessmentPage / RealtimeAnalysis) | 起会话后**先拿铸号再用**,face/gesture 不再用旧 UUID |

**前端在 `/interview/start` 之前**就发帧的情况(`RealtimeAnalysis` 可能先开摄像头):此时还没有铸号。
**处理方式见 §5.3。**

## 5. 接口契约

### 5.1 读侧选择规则

```
输入:目标 session_id(显式给定,或由"最新一场"推出)
每个模态:在 data/logs 下找**文件名里 session_id 恰好等于目标**的那份
  - 找到且可读   -> 记 (sid, 已读入)
  - 找到但读不出 -> 记 (sid, 未读到数据)   ← 不许静默丢
  - 没找到       -> 记 (sid, 缺失)
```

"最新一场"= 在 `data/logs` 里出现的**所有合法 `session_id`** 中取文件名时间戳最大的那个
(合法 = 匹配现有正则,即铸造形态)。

### 5.2 报告头披露(替代现在的两态)

```
本场会话:20260924_221811_9212
  面部 · 已读入        (1 行)
  手势 · 已读入        (1 行)
  语音（面试） · 未读到数据(文件存在但为空)
  研究语音 · 缺失
```

**同场/不同场那句话随之取消** —— 按 id 选之后,不存在"不同场"这种状态;真正要报的是
**哪几个模态没进来、为什么**。

### 5.3 前端 id 的生命周期

- **会话开始前**(`/interview/start` 未调用):face/gesture **不带 id**(落 `NONE` 桶,
  与现在一致),或前端**先调 start 再开摄像头** —— **取后者**,因为它让实时分析从一开始就
  属于这一场。
- **会话开始后**:一律用服务端返回的 `session_id`。
- `interview.start()` 的返回值里必须有 `session_id`(M1 已保证),前端**保存到 localStorage**
  并替换掉旧的 UUID 键(**迁移:清掉 `assessment_session_id` / `face_session_id` 里存的旧 UUID**,
  否则老用户会一直用旧值)。

### 5.4 契约测试(必须能说出"哪个改动会让它红")

- 按 id 选:造两个不同 id 的日志目录,**断言只取目标的那些**(红法:退回按时间戳取最新)
- 未读到数据:目标 id 的语音日志是空文件 → **断言披露里出现它**(红法:退回 I4 的"只记读到的")
- 缺省取最新:不给 id → 断言取到文件名时间戳最大的那个 id,且**报告头写明了它是谁**
- 前端 id:`interview.start()` 之后,face/gesture 的 URL 里带的是**铸号**而不是 localStorage 里的 UUID

## 6. 错误处理

| 情形 | 行为 |
|---|---|
| 目标 id 一个模态都没找到 | 报告仍生成,头里**逐条列出缺什么**;不抛 |
| 目标 id 全部模态都缺 | 生成报告并**显式说明本场没有任何日志**;**不**回退去拼别的场次 |
| 前端在拿到铸号前发帧 | 那些帧落 `NONE`(既有行为);**报告头要点出 `NONE` 桶存在**,提示有帧没归入本场 |
| 老用户的 localStorage 里是旧 UUID | **启动时清掉**;否则 id 会一直是旧值(§5.3) |

## 8. 已知未满足项与待办

1. **`refresh_manifest` 的真消费者本轮不做** —— M2 的原始定义里含它,但**披露已经用更直接的方式
   覆盖了同一个需求**:看**加载器实际读到了什么**,而不是看清单**声称应该有什么**。
   `session.json` 还在 `~/shared/jingxin_recordings/`(仓库外),让报告去读它等于新增一条跨目录依赖,
   收益不抵成本。**若使用者认为该做,这是一句话就能加回来的。**
2. **409 归属契约不做** —— 单会话下不触发;它是 D1 落地之后才谈得上的下一步。
3. **`NONE` 桶仍然跨天累积**,且所有无 id 客户端共享一个 pipeline(承 M1 的 deferred)。
4. **哨兵值歧义**(50.0 / 0.0 与真实值撞车)单列 —— 它现在会让"未读到数据"和被测量值长得一样,
   与 M2 的诚实轴同源,但改动点在分析器与前端显示,不在读侧。
5. **前端"一直显示在录音"的状态机**、**无产出方的字段**(语音流畅度)—— 前端独立问题。
6. **`data/output/` 里历史报告会持续累积**(每次生成一批 plotly HTML)—— 与已记录的 `NONE` 轮转同源。
