# JingXin 面试数据录制需求

- 日期:2026-09-22
- 状态:待使用者决定何时执行
- 依据:`2026-09-22-测评回复_心理测量学审查.md`、`2026-09-21-jingxin-feature-redesign-design.md`、`2026-09-22-jingxin-report-layer-evidence-gate-design.md`(增补)
- 本文件回答一个问题:**"现在要不要录数据?录的话要满足什么?"**
- **结论先放前面:现阶段只需要"阶段 A(3–5 场)",且必须满足三个硬前提;不要为了 ① 录数据。**

---

## 0. 一句话结论

**① 报告层的输出不会因为数据变多而改变。** 实测:同一套代码,4 帧空壳会话与 **14208 行完整会话**的结果**完全相同 —— 21/21 个指标槽全被拦下**。拦它们的是**封停名单**(列本身有缺陷)和**恒定**(列整场不变),不是样本量。

所以:**录数据的目的是 M2/M3 的采集层验证,不是 ①。**

---

## 1. 三个阶段,需求完全不同

| 阶段 | 用来做什么 | 规模 | 需要标注 | 前置条件 |
|---|---|---|---|---|
| **A** | 验证 M2 时间基修复、M3 的 L0 列行为 | **3–5 场完整会话** | 否 | 见 §2 的三个硬前提 |
| **B** | 自评量表标定(M5) | 由**统计功效**反推,门槛写进标定报告,**不写死场次** | 是(候选人自评) | **科技伦理审查通过** + M1 完成 |
| **C** | 雇主侧用于筛选 | 每群体 **≥200–300 人** | 是 | 差分效度、增量效度、公平性检验、合规审查 |

**本文件只规定阶段 A。** B/C 的前提尚未满足,现在录了也用不上。

## 2. 阶段 A 的三个硬前提(缺一不可)

### 前提 1:M1 的 `session_id` 链路必须先修好

**理由**:三份日志现在**都不写 `session_id`** —— 实测部分 `face_au_log_*.csv` 首列是 `session_id`、另一部分是 `timestamp`;语音(`unix_timestamp`)与手势日志都没有。报告层"各取最新"的后果是实测拼出过 **「5 月的脸 + 2 月的语音」**。

**在链路修好之前录,数据天生对不上号,录了等于白录。**

### 前提 2:必须保留原始媒体

**理由**:现有 55 个日志文件里,**一份原始视频/音频都没留**(`data/input/` 是空的,全仓无 `*.mp4`/`*.wav`)。而当前管线的缺陷是**已知**的:

- `FRAME_SKIP = 3` 但 `VideoPipeline(fps=30)` → 有效采样 ≈10fps,**时间量全部错 3 倍**
- `timestamp = time.time()` → 挂钟时间,与真时长只相关 0.666,**中位是真时长的 2.32 倍**
- `is_blink` 恒 0(值写进深拷贝没写回)
- `au4_frown` 的 landmark 用了 lm[276]+lm[33](眉-眼角),**86~92% 触地板**

**没有原始媒体 → 这些缺陷被永久烘进数据,事后无法重抽。**
**有原始媒体 → M3 修好后重新抽一遍即可。**

### 前提 3:不要在本轮(M3 之前)采自评量表

**理由**:审查 §7.2 明确 —— 按《科技伦理审查办法(试行)》第 2 条第(一)项,以人为研究参与者(含"利用个人信息数据")的科技活动**必须通过科技伦理审查**,2023-12-01 已施行。采集候选人自评量表用于标定落入该条。

**这是强制项,不是建议项。** 在审查通过前采集,是程序违规。

⚠️ 另外:知情同意要求告知用途,而告知用途会污染自评 —— 这个结构性矛盾在阶段 B 才需要解决。

## 3. 每场必须采集的东西

### 3.1 原始媒体(存仓库外,见 §4 路径)

| 项 | 要求 | 为什么 |
|---|---|---|
| 视频 | **每路摄像头一份原始文件**,不做任何转码/裁剪 | 转码会改帧率;裁剪会丢人脸尺度信息 |
| 音频 | 原始音频,或从视频分离的无损音轨 | 停顿检测与 VAD 需要完整音轨(含末尾静音) |
| 真实帧率 | 记录**实际**帧率,不要写死 30 | 当前 bug 就是 `FRAME_SKIP` 与 `fps` 不一致 |
| 音频采样率 | 记录实际采样率(代码里假设 16000) | `duration_sec = len(audio)/16000` |

### 3.2 必须同时记录的元数据

| 项 | 为什么必须 | 依据 |
|---|---|---|
| **`session_id`** | 贯穿三模块的唯一键 | 前提 1;现在是"各取最新" |
| **提问开始/结束时刻** | `response_latency` 目前**不可得** | 设计文档 §11.1 —— 采集流程暂无问题时间戳,该指标只能降级或删 |
| **题目 ID + 题目难度** | 审查称"**最明显的遗漏**" —— 数据集里有 74 个不同题目,你的协变量里一个都没有 | 审查 §3.5 第 7 条 |
| **性别 / 年龄 / 母语 / 方言** | 审查称你对"取景/设备"有协变量意识,对**人的生理属性**没有,而后者对 F/V 族影响更大 | 审查 §3.5 第 6 条。实测 `pitch_mean` 的 **ICC = 0.723** —— 它主要是解剖常量,**可能让分数部分成为性别探测器** |
| **摄像头型号 / 分辨率 / 镜头距离 / 光照** | `energy` 实测 **ICC = 0.654**,是设备增益/距离代理 | 审查 §3.3 |
| **麦克风增益设置** | 同上 | 审查 §3.3 |
| **面试官结构化评分** | 审查 Q3(f):"**你现在最该补的真值,成本最低、最贴用途**" —— 你本来就有面试官 | 审查 §4(f) |
| **知情同意记录** | 数据类型、用途、留存期、**能否拒绝且不影响录用**、是否含自动决策、申诉渠道 | 审查 §7.4 第 1 条 |

### 3.3 采集环境要求

| 项 | 要求 | 为什么 |
|---|---|---|
| **固定机位、固定距离** | 全程不变 | 审查 §5(d) 把"**人脸尺度**"列为最低可分析条件之一;`symmetry_score` 的教训就是"未除人脸尺度 → 取景代理" |
| **手部可见** | 尽量保证手在画面内 | 实测手部 10 列中 **87%/85% 的有效帧为 0**(手不入镜) |
| **采样率全程一致** | 不要中途改设置 | 审查 §5(d) 列为最低可分析条件 |
| **光照稳定** | 避免逆光变化 | 影响 landmark 稳定性 |

### 3.4 每场结束后的当场核对(检查清单)

录完**当场**逐条打勾,不要事后补:

- [ ] `session_id` 已写入三份日志(脸 / 手势 / 语音)
- [ ] 原始视频与音频已落盘,且**文件数与模态数一致**
- [ ] 记录的实际帧率 / 采样率 / 分辨率,与配置一致
- [ ] 提问开始与结束时刻已记录
- [ ] 题目 ID 与难度已记录
- [ ] 候选人生理属性协变量已记录(性别/年龄/母语/方言)
- [ ] 设备与取景元数据已记录
- [ ] 面试官结构化评分已记录
- [ ] 知情同意已签署并归档
- [ ] **未采集自评量表**(阶段 A 不采,见前提 3)

## 4. 存放路径(仓库外)

**原始媒体不得进 git。** 仓库现有 `data/logs`(16MB)已被跟踪,再放视频会把仓库撑爆且不可逆。

| 内容 | 建议路径(WSL 侧) | 对应 Windows 侧 |
|---|---|---|
| **原始媒体** | `~/shared/jingxin_recordings/{session_id}/` | `D:\Shared\jingxin_recordings\{session_id}\` |
| 抽取出的特征 | 仓库内 `data/logs/*.csv`(现状不变) | — |
| 标注 / 元数据 | 仓库内 `sessions/{session_id}/labels.json` | — |

`~/shared` 与 `D:\Shared` 是双系统共享目录,自动挂载。

每场目录结构建议:

```
~/shared/jingxin_recordings/{session_id}/
├── video/
│   ├── cam0.mp4            # 原始,不转码
│   └── cam1.mp4            # 若有第二路
├── audio/
│   └── raw.wav             # 或从视频分离的无损音轨
├── meta.json               # 见 §3.2 的元数据 + §3.3 的设备参数
└── consent/                # 知情同意归档
```

`meta.json` 最小字段:

```json
{
  "session_id": "20260922_143052_a1b2c3",
  "recorded_at": "2026-09-22T14:30:52+08:00",
  "capture": {
    "video_fps_actual": 0.0,
    "resolution": "1920x1080",
    "camera_distance_cm": 0,
    "lighting": "",
    "audio_sample_rate": 16000,
    "mic_gain_db": 0
  },
  "candidate": {
    "sex": "", "age": 0, "native_language": "", "dialect_region": ""
  },
  "questions": [
    { "qid": "", "difficulty": "", "start_ts": 0.0, "end_ts": 0.0 }
  ],
  "interviewer_ratings": {
    "logical_thinking": null,
    "communication": null,
    "confidence": null
  }
}
```

字段名以实际实现为准;此处给的是**必须覆盖的信息项**,不是最终 schema。

## 5. 明确不要做的事

| 不要 | 原因 |
|---|---|
| **不要为了 ① 录数据** | ① 的输出不随数据量变化(实测 4 帧 vs 14208 行结果相同) |
| **不要在 M1 的 `session_id` 链路修好前录** | 数据对不上号,且无从追溯 |
| **不要在伦理审查通过前采自评量表** | 《科技伦理审查办法(试行)》第 2 条第(一)项,**强制项** |
| **不要把原始媒体放进 git** | 仓库已有 16MB 日志被跟踪,视频会让它不可逆地膨胀 |
| **不要转码 / 裁剪原始视频** | 改帧率会破坏时间基;裁剪会丢人脸尺度信息 |
| **不要让采集端知道标注** | 设计文档 §2.1 目标 4:采集与标注解耦 |

---

## 6. 更便宜的路(先走这两条)

在录制之前,有两件**不需要新录任何数据**的事,性价比更高:

1. **审查的"第一件":用已有数据集做人 vs 情境的方差分解。** 对 RecruitView 的 331 人 × ~6 片段、MIT 的 69 人 × pre/post 算 ICC,直接把"哪些指标有资格进 L2"定下来。数据已在盘上。
2. **MIT 的 pre/post 结构**是免费的"人内前后测 + 实验干预"设计(69 人 × 2 场,中间一次职业顾问干预),可一次拿到:重测信度、状态类 vs 特质类特征的经验切分、以及标注对干预的敏感性检验。设计文档附录 D 已列出,**成本约一次脚本运行**。
