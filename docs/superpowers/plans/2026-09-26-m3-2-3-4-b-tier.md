# M3.2 / M3.3 / M3.4 —— B 档 33 条逐列重构(计划)

> 上游:`docs/下一步.md` §0.11 §11.2 / §11.6。
> **任务清单不在本文件里** —— 它是 `l0_columns.json` 里 `status=pending` 且 `maturity=B` 的那些行。
> 本文件只写**怎么做、按什么顺序、怎么算做完**。抄进本文件的数字会过期,所以一个都不抄。

## 0. 为什么是这 33 条(它们干什么用的)

L0 是**最底层的原始测量层**,报告里每个指标都由它聚合而来。这 33 列现在的问题**不是"没算",
而是"算错了、却返回一个看着正常的数"** —— 不出异常、不是空值,所以从上到下没人发现。

表里写明的实例(每条的 `acceptance` 里都有实测症状):

| 列 | 现状症状(表里原文有实测数) |
|---|---|
| `au4_frown` | 用错 landmark,86~92% 的帧贴地板 ⟹ 报告里"皱眉"实际是个常数 |
| `symmetry_score` | 未除人脸尺度,会话内近常量 |
| `pitch_trend` | 吐原始 Hz 差而非半音,换人说话不可比 |
| `*_jitter` 一族 | 除以裸常量 / 不除时间 ⟹ 随帧率与离镜头远近漂 |

**口径错了以后,上层再怎么写都不可能对。** 这 33 条就是"报告说真话"的地基。

## 2. 三条纪律(每一条都由本仓的实测踩出来,违反它们就要重做)

1. **说「验证过」之前先问:我跑的这条会不会执行到我要证的那段代码?**
   - 反例(本仓已发生 5 次):拿合并门当采集层改动的证据(`experiments/duration_audit/` 读盘上静态
     CSV、**不 import 被改代码** ⟹ 对该类改动**结构上不可见**);只核清单当验证。
   - 本计划里的含义:每列的验收**必须跑真产出方**(三个服务 logger 那条活路径,或
     `experiments/replay_retained.py` 的重放腿),**不许在测试里重写一遍公式再自证**。
2. **散文里的数会静默过期。** 数只说一次(放 `l0_columns.json` 的结构化字段),能算的就别手写。
3. **重放必须喂留存账本的 `declared_ts`。** 用墙钟重放会得出"推理不可复现"的**假**结论
   (根因是 landmarker 的 `VIDEO` 模式拿时间戳当模型输入)。样板:`experiments/replay_retained.py`。

|---|---|---|---|
| **B0** | E7 键/列名对齐 | report_frontend | 1(见 §4,**已停在裁定**) |

## 4. ★ B0 已停在裁定点 —— 需要一个决定才能继续

E7(`docs/下一步.md` §11.4):`evidence_gate.py` 里两条 `permanent=True` 的永久封停
**打不中目标**,于是两个本该被拦下的量在报告里看起来正常。

**天真改法会引入新错,已实测证明:**

```
键 'is_calibrated' 会命中: ['gesture__is_calibrated']                        ← 对
键 'head_tilt'     会命中: ['gesture__head_tilt', 'gesture__head_tilt_angle'] ← 错!
```

`is_quarantined` 是**子串**匹配(`s in k`),而 `head_tilt` 是 `head_tilt_angle` 的子串;
`head_tilt_angle` 在 L0 表里是 **`maturity=A` / `status=implemented` 的保留列**。
把键改成裸 `head_tilt` ⟹ **误封一个要留的列**。

**待裁定(三选一,影响 35 条封停的共享匹配规则):**

| 选项 | 做法 | 风险 |
|---|---|---|
| (a) 逐条精确匹配 | 给这两条加"整键相等"语义,其余 33 条保持子串 | 规则出现两种语义,得写清哪个优先 |
| (b) 剥模态前缀后精确比 | 匹配前把 `<模态>__` 剥掉再比全等 | 改的是**所有人**的匹配口径,33 条要重验 |
| (c) 显式排除键 | 保留子串匹配,加 `head_tilt_angle` 的豁免 | 豁免名单会累积,但改动面最小 |

**在裁定之前 B1/B2/B3 不受阻,可以照做** —— 只有 B0 卡住。

## 5. 每列的完成契约

一条列算"做完",同时满足:

1. `l0_columns.json` 该行 `status: pending → implemented`(或按 `acceptance` 判删并写明理由)。
2. `acceptance` 里点名的**每一个**症状,有一条**跑真产出方**的证据说明它消失了
   (真产出方 = 三个服务 logger 的活路径 / `replay_retained.py` 重放腿)。
3. 三场正式素材(`20260926_153202_2b11` / `153854_1592` / `155559_caf0`)上实测过,
   不是合成数据。
4. 若新增/改动日志列:`tests/test_l0_column_table.py` 的双向钉子仍是绿
   (方 1:每条活列要么在表里、要么在白名单里;方 2:每条 `implemented` 行真被三个 logger 产出)。
5. 全量套件绿。

## 6. 复核纪律(上一支花了 11 次独立复核 + 7 次修复轮,**太多**)

- **同型小任务合并成一次复核**:16 个 jitter 一次;10 条面部一次。
- 复核前的自检:**这条验收判据真的可达吗?**(上一支的教训:判据写完先自己走一遍)。
- 不做"一个小任务一个复核轮"。

## 7. 已知的坑(动手前先读,别重新踩)

- **重放只在面部有腿**(`replay_retained.py` 没有手势/语音腿)⟹ B2 可直接用重放;
  **B3 要先给重放加手势腿**,否则"验证"只能靠活路径。
- `_试跑/` 9 场**不是素材**(`meta.json` 与正式素材同款、区分不出,判据只有目录位置)——
  别拿它们当验收集,但可以当回归集。
- 三个服务改了采集层代码**必须重启**才生效;启动要 `setsid` 脱离终端,否则成 T 态。
- 服务重启后**旧进程产物会被误当成新码产物** —— 验收前先确认 `sid == pid` 且 `TTY = ?`。
