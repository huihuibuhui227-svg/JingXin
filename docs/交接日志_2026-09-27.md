## 2. 怎么访问(两条路,都是「安全上下文」)

> **为什么必须是这两条之一**:浏览器规定 `getUserMedia`(摄像头/麦克风)只在
> 安全上下文里存在 —— 即 `https://` 或 `http://localhost`。**`http://<IP>` 两条都不占**
> ⟹ `navigator.mediaDevices === undefined` ⟹ 摄像头在 JS 层面就不存在。
> 实测对比:`http://192.168.72.30:5173` → `isSecureContext=False, mediaDevices=undefined`;
> `http://localhost:15173`(隧道)→ `True, object`。**没有开关可开。**

### 路 A(推荐):直接开网址,零配置

```
https://gpuserver.tail4ffce2.ts.net:5173
```

前提:那台电脑在 tailnet `476447171@` 里。第一次会弹摄像头授权,点允许。

### 路 B(备选):SSH 隧道

```bash
bash tools/tunnel_to_server.sh          # 默认 zgy@192.168.72.30
JX_SERVER=zgy@100.64.191.35 bash tools/tunnel_to_server.sh
# 然后浏览器开 http://localhost:5173
```

路 B 的好处:**只要 22 端口可达就能用**,不需要进 tailnet。今晚在 Windows Edge 上
实测取到了真摄像头(`video:1 audio:1`,设备 `Integrated Camera`)。

### 五条 tailscale serve(路 A 的基础)

```bash
tailscale serve --bg --https=5173 http://127.0.0.1:5173    # 前端
tailscale serve --bg --https=5000 http://127.0.0.1:5000    # 面板
tailscale serve --bg --https=8000 http://127.0.0.1:8000    # face
tailscale serve --bg --https=8001 http://127.0.0.1:8001    # voice
tailscale serve --bg --https=8002 http://127.0.0.1:8002    # gesture
tailscale serve status
```

## 7. ★ 下一步:改「实时分析模块」(`/analysis`)

### 7.1 它现在是什么

**文件**:`~/JingXin/frontend/src/pages/RealtimeAnalysis.tsx`(路由 `/analysis`,首页第 4 个入口)

**它做什么**:开摄像头 → 按帧率抽帧 → 每帧发给 face/gesture 分析 → 把结果画在时间线上。

### 7.2 它的三个已知限制(改之前先知道)

```tsx
const { videoRef, canvasRef, startCamera, stopCamera, startCapture, stopCapture } = useCamera({
  onFrame: async (frame) => {
    frameCountRef.current += 1;
    if (frameCountRef.current % 10 !== 0) return;   // ← 限制 ②
    ... faceApi.analyzeImage(frame) / gestureApi.analyzeGesture(frame)
  },
});
```

| # | 限制 | 后果 |
|---|---|---|
| ① | **只传了 `onFrame`,没传 `onVideoReady`** | 而 `useCamera` **只在有 `onVideoReady` 时才挂 `MediaRecorder`** ⟹ **不产生视频文件、不产生音频、没有转写** |
| ② | `% 10` 过滤 | 配 `frameRate: 5` 时**实际约 0.5 fps**(每 2 秒一帧) |
| ③ | **不自己起会话** | 发出去的帧没有 `session_id` ⟹ 全落 **NONE 桶** ⟹ 报告里不属于任何一场 |

### 7.3 `useCamera` 已经支持的东西(不用改 hook)

```ts
interface UseCameraProps {
  onFrame?: (frame: Blob) => void;
  frameRate?: number;
  onVideoReady?: (video: Blob) => void | Promise<void>;   // ★ 传了它才会录像
  onDegraded?: (reason: string) => void;                  // 降级了要说出来
}
```

**`onVideoReady` 有一个契约,别踩**:

> 录像在整场里**只活在内存**中,所以 hook 会挂一个 `beforeunload` 拦截(刷新/关页
> 就把整场录像永久丢了)。那个拦截**一直留到你返回的 promise 落定**为止 ——
> **blob 到手不等于存下了**。做上传的调用方**必须把上传的 promise return 出来**;
> 不 return 的话拦截会在 `onstop` 时立刻撤掉,上传期间就没人拦。

### 7.4 要做的改动(建议顺序)

1. **起会话**:进页面时铸号并 `setSessionId`。参考实现见
   `src/hooks/useAssessment.ts`(`interviewApi.start()` → `setSessionId(...)`)。
   不起会话 ⟹ ③ 永远修不掉。
2. **接上录像**:给 `useCamera` 传 `onVideoReady`,里面调 `sessionApi.uploadMedia(video)`
   **并 `return` 那个 promise**。视频+音频在同一条流里(R5 实测 `audio:live, video:live`),
   **一个 blob 两样都有**,不用另存音频。
3. **处理降级**:传 `onDegraded`,把"这一场只拿到摄像头没拿到麦克风"这类情况
   显示出来 —— 否则这一场和正常那场的素材长得一样。
4. **(可选)帧率**:`% 10` 是你自己的节流,想快就调小或去掉;但注意后端要扛得住。

### 7.5 改完之后怎么验

1. 用**别的电脑**开 `https://gpuserver.tail4ffce2.ts.net:5173/analysis`(或隧道 + localhost)
2. 录一小段 → 停 → 看落盘:`~/JingXin/recordings/<新SID>/media/` 里应当出现
   `camera.webm`(视频+音频),并且 `media/face/`、`media/gesture/` 有帧
3. 三份 CSV 的**文件名与首列**都该是那个 SID(不是 `NONE`)
4. 出报告:`python -m report_frontend.report_generator --session-id <SID>`

**注意**:`/analysis` 这条路没有题库、没有 `ask_start/ask_end`,所以
`reaction_time`、`response_latency` 那类**依赖提问时刻**的量**不会有值**。
这是设计如此,报告里会如实显示"有效样本不足"。
