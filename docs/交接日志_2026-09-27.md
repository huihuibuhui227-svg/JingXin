## 2. 怎么访问(两条路,都是「安全上下文」)

> **为什么必须是这两条之一**:浏览器规定 `getUserMedia`(摄像头/麦克风)只在
> 安全上下文里存在 —— 即 `https://` 或 `http://localhost`。**`http://<IP>` 两条都不占**
> ⟹ `navigator.mediaDevices === undefined` ⟹ 摄像头在 JS 层面就不存在。
> 实测对比:`http://192.168.72.30:5173` → `isSecureContext=False, mediaDevices=undefined`;
> `http://localhost:15173`(隧道)→ `True, object`。**没有开关可开。**

### 路 A(推荐):直接开网址,零配置

```
https://gpuserver.tail4ffce2.ts.net:5173
```

前提:那台电脑在 tailnet `476447171@` 里。第一次会弹摄像头授权,点允许。

### 路 B(备选):SSH 隧道

```bash
bash tools/tunnel_to_server.sh          # 默认 zgy@192.168.72.30
JX_SERVER=zgy@100.64.191.35 bash tools/tunnel_to_server.sh
# 然后浏览器开 http://localhost:5173
```

路 B 的好处:**只要 22 端口可达就能用**,不需要进 tailnet。今晚在 Windows Edge 上
实测取到了真摄像头(`video:1 audio:1`,设备 `Integrated Camera`)。

### 五条 tailscale serve(路 A 的基础)

```bash

tailscale serve --bg --https=5000 http://127.0.0.1:5000    # 面板
tailscale serve --bg --https=8000 http://127.0.0.1:8000    # face
tailscale serve --bg --https=8001 http://127.0.0.1:8001    # voice
```

## 7. ★ 下一步:改「实时分析模块」(`/analysis`)

> **2026-09-27 晚:已改完。** §7.1–§7.5 保留为**当时的现状与做法**(过程记录)。
> 改了什么、以及改的时候踩到的坑,见 **§8.1**。

### 7.1 它现在是什么

**文件**:`~/JingXin/frontend/src/pages/RealtimeAnalysis.tsx`(路由 `/analysis`,首页第 4 个入口)

**它做什么**:开摄像头 → 按帧率抽帧 → 每帧发给 face/gesture 分析 → 把结果画在时间线上。

### 7.2 它的三个已知限制(改之前先知道)

```tsx
const { videoRef, canvasRef, startCamera, stopCamera, startCapture, stopCapture } = useCamera({
  onFrame: async (frame) => {
    frameCountRef.current += 1;
    if (frameCountRef.current % 10 !== 0) return;   // ← 限制 ②
    ... faceApi.analyzeImage(frame) / gestureApi.analyzeGesture(frame)
  },
});
```

| # | 限制 | 后果 |
|---|---|---|
| ① | **只传了 `onFrame`,没传 `onVideoReady`** | 而 `useCamera` **只在有 `onVideoReady` 时才挂 `MediaRecorder`** ⟹ **不产生视频文件、不产生音频、没有转写** |
| ② | `% 10` 过滤 | 配 `frameRate: 5` 时**实际约 0.5 fps**(每 2 秒一帧) |
| ③ | **不自己起会话** | 发出去的帧没有 `session_id` ⟹ 全落 **NONE 桶** ⟹ 报告里不属于任何一场 |

### 7.3 `useCamera` 已经支持的东西(不用改 hook)

```ts
interface UseCameraProps {
  onFrame?: (frame: Blob) => void;
  frameRate?: number;
  onVideoReady?: (video: Blob) => void | Promise<void>;   // ★ 传了它才会录像
  onDegraded?: (reason: string) => void;                  // 降级了要说出来
}
```

**`onVideoReady` 有一个契约,别踩**:

> 录像在整场里**只活在内存**中,所以 hook 会挂一个 `beforeunload` 拦截(刷新/关页
> 就把整场录像永久丢了)。那个拦截**一直留到你返回的 promise 落定**为止 ——
> **blob 到手不等于存下了**。做上传的调用方**必须把上传的 promise return 出来**;
> 不 return 的话拦截会在 `onstop` 时立刻撤掉,上传期间就没人拦。

### 7.4 要做的改动(建议顺序)

1. **起会话**:进页面时铸号并 `setSessionId`。参考实现见
   `src/hooks/useAssessment.ts`(`interviewApi.start()` → `setSessionId(...)`)。
   不起会话 ⟹ ③ 永远修不掉。
2. **接上录像**:给 `useCamera` 传 `onVideoReady`,里面调 `sessionApi.uploadMedia(video)`
   **并 `return` 那个 promise**。视频+音频在同一条流里(R5 实测 `audio:live, video:live`),
   **一个 blob 两样都有**,不用另存音频。
3. **处理降级**:传 `onDegraded`,把"这一场只拿到摄像头没拿到麦克风"这类情况
   显示出来 —— 否则这一场和正常那场的素材长得一样。
4. **(可选)帧率**:`% 10` 是你自己的节流,想快就调小或去掉;但注意后端要扛得住。

### 7.5 改完之后怎么验

1. 用**别的电脑**开 `https://gpuserver.tail4ffce2.ts.net:5173/analysis`(或隧道 + localhost)
2. 录一小段 → 停 → 看落盘:`~/JingXin/recordings/<新SID>/media/` 里应当出现
   `camera.webm`(视频+音频),并且 `media/face/`、`media/gesture/` 有帧
3. 三份 CSV 的**文件名与首列**都该是那个 SID(不是 `NONE`)
4. 出报告:`python -m report_frontend.report_generator --session-id <SID>`

**注意**:`/analysis` 这条路没有题库、没有 `ask_start/ask_end`,所以
`reaction_time`、`response_latency` 那类**依赖提问时刻**的量**不会有值**。
这是设计如此,报告里会如实显示"有效样本不足"。

   ```
   ~/JingXin/recordings/20260927_210506-05-钱七-2021005-化学学院__20260927_210506_d1c4/
   ```

   ⚠️ **`sid` 必须留在目录名尾部** —— 它同时是 `data/logs/` 里三份日志的文件名,而报告层
   按那个正则找日志。目录名可改,但必须**还能从 sid 推出来**:`root()/<sid>` 在
   **四个地方**各自算过一遍,失效的形态是**素材静默写不进去**。
   解析规则在 `media_retention.resolve_recording_dir`(三处共用):
   1) `root()/<sid>` 在就用它 ⟹ **历史素材与没标的场次照旧不动**;
   2) 否则按**后缀** `__<sid>` 找(不是 `sid in name`,免得 `x__<sid>_extra` 误配);
   3) 都没有 ⟹ 返回旧形态路径,由调用方决定建不建。
   新建/独立的调用方要一起看:`session_meta._session_dir`、
   `transcript_store.recording_dir`(它在 `root=None` 时**委托**给 media_retention;
   自己按 `root()/<sid>` 算的话会把一场劈成两个目录,**两边都"成功"**)。
   守卫:标签是客户端可控的、现在会进目录名 ⟹ `label_dir_name` 挡路径分隔符/NUL/
   控制字符/以点开头,并有 **240 字节**的目录名上限(文件系统 255,中文 3 字节/字)。

8. **从这台笔记本连服务器:`ssh zgy@gpuserver` 解析不了**(没有那个 Host 别名)。
   用 `ssh zgy@192.168.72.30`,免密可用。`~/.ssh/config` 里那个 `Host target`
   指向的是**另一台**机器(`192.168.1.102`),不是 gpuserver。

9. **`web-access` 的 CDP 代理(3456)连不上 Windows Edge。** 症状:check-deps
   一直 `proxy: connecting...` 然后 `❌ 连接超时`。根因:
   `browser-discovery.mjs` 从 **WSL 本地**的 `~/.config/microsoft-edge/DevToolsActivePort`
   读 `wsPath`(一个**过期的 UUID**),而 9222 经 WSL 转发到的是 **Windows** Edge
   (另一个 UUID)⟹ 每轮都对不上。**裸 WebSocket 直连 9222 是通的**。
   绕法:自己写个 CDP 客户端,每次从 `http://127.0.0.1:9222/json/version` **现取**
   `webSocketDebuggerUrl`,不自造缓存。(顺带:`Browser.grantPermissions` 可以对
   `http://localhost:5173` 预授权摄像头/麦克风,免掉弹窗。)
   ⚠️ 另一个坑:**antd 会在「两个汉字」的按钮里自动插一个空格**(`保存` 渲染成
   `保 存`)⟹ 按文案找按钮时先 `textContent.replace(/\s/g,'')` 再 `includes`
   (四个字的按钮如「确定停止」不受影响 —— 所以这个坑只在两字按钮上炸)。

## 8.2 ★ 2026-09-28:一场真实的素材丢失事故,与三处缺陷

> ⚠️ **本文件会 push 到公开仓库 ⟹ 一律不写受试者的姓名 / 学号 / 院系,只用 `session_id`。**
> 2026-09-28 我在这份文档里抄了 6 个真实姓名(从录制目录名带过来的),**push 前的
> 检查把它拦下了** —— 一次都没发出去,但这是**运气**,不是纪律。本仓已有的那条
> 「原句不进仓库」(M1)是同一件事的语音版,这条是它的**元数据版**:
> `label.json` 里的姓名/学号是**素材**,不是文档内容。
>
> 顺带:这也说明**标注功能天然会产生可识别信息**。写文档、发截图、贴日志时都要先想一步。

> 这一节比 §8.1 重要 —— §8.1 记的是"改的时候踩到的坑",这一节记的是**上线之后
> 在真实使用中炸出来的**,而且**已经造成了不可逆的损失**。下一轮接手请先读这一节。

### 8.2.1 事故:2.1 GB 原生录像被静默覆盖

**经过**:使用者当天用 `/analysis` 连续给**很多个学生**录面试。他的用法是
**一个页面不关,录完一个点「停止录制」、再点「开始录制」录下一个**。

**结果**:9 次录制全部挤进同一个 `session_id`,每次停止录制上传的 `camera.webm`
把上一次**覆盖**掉。两个场次受害:

| 场次 | 录制次数 | 上传总量 | 现存 | 丢失 |
|---|---|---|---|---|
| `20260928_180131_8102` | 9 | 2,088.7 MB | 130.3 MB | **1,958 MB**(8 段) |
| `20260928_172642_1320` | 4 | 161.9 MB | 13.3 MB | **148.6 MB**(3 段) |

**根因是两处叠加**:

1. **前端**把"一个页面连录多个学生"建模成了**一场** —— 铸号原本是"只铸一次"
   (`mintRef` 复用),理由是"停一次再开一次不能再铸,否则会把一场的数据劈成两场"。
   那个假设是错的:**一次录制 = 一场**。
2. **服务端**允许覆盖,而且是**静默**的:`retain_uploaded_video` 用
   `write_bytes` 原地重写,**回 200 + `stored: true`** —— 每一次覆盖都"成功"。
   它的 docstring 当时写着"第二次上传覆盖它,账本仍一次一记,所以有据可查
   (测试钉住了这一点)"。**账本那几行 sha 只能证明"曾经有过一份",救不回字节。**

> **教训(值得单独记)**:账本记的是"发生过什么",不是"字节还在不在"。
> 一个把"原始素材不可再生"当核心价值的系统,**覆盖原始素材不该是静默的**。

**抢救**:覆盖是原地重写 ⟹ 超出当前文件末尾的物理块曾被释放,理论上留着更早那几份的
**尾部**。算出来可能拿回 4 段（约 40–140 MB/段）。**但同日同盘还写了 1.5 GB 的帧**
(face 752 MB + gesture 752 MB)，空闲块很可能已被复用 ⟹ 未做探测，使用者裁定放弃。
用到的命令与推理留在 §8.2.5。

### 8.2.2 三处缺陷(第一、二处已修并上线)

| # | 缺陷 | 后果 | 状态 |
|---|---|---|---|
| ① | 一个页面 = 一场(铸号只一次) | 多学生挤进同一场,互相覆盖 | ✅ 已修 |
| ② | 服务端允许静默覆盖 `camera.webm` | 覆盖不可逆且回 200 | ✅ 已修 |
| ③ | **摄像头 track 死了不报警** | 画面冻结后**继续上报同一张图**,静默产出"看着有、其实是一张图"的素材 | ❌ **未修** |

**①的修法**(前端 `ca9824f`):`startNewSession()` 取代 `ensureSession()`,每次点
「开始录制」都铸**新号**;配套 `resetPerSessionState()` 清掉上一场留在页面上的状态
(帧计数 / 时间线 / 降级 / 标注 —— 不清会串场)。
**外加保存门禁**:`onVideoReady` 返回的 promise **只在留存确认之后才落定**
(`useCamera` 拿它当"何时撤掉刷新拦截"的信号 ⟹ 失败时让它**继续悬着**,
blob 留在内存里、拦截还在)。遮罩式弹窗,保存中不给关;失败给「重试上传」+
「放弃本场」(二次确认);`saveState !== 'idle'` 期间**「开始录制」禁用**。

**②的修法**(后端 `5679a11`):新增 `CameraAlreadyRetained`,`retain_uploaded_video`
在写**之前**检查文件是否已存在,在则**抛**;端点接住 → **409**。
⚠️ **守卫必须放在那个 `except Exception` 的外面** —— 放里面会被当成"写失败"吞成
degraded,"拒绝覆盖"就退化成静默降级(有测试钉住这一点)。

**测试反转**:`test_second_upload_overwrites_the_file_but_the_ledger_keeps_both`
→ `test_second_upload_is_refused_and_the_first_one_survives`,断言第一份**逐字节没动**、
被拒那次**不进账本**。`pytest` 655 → **658 passed**。

**③ 的现象与状态**:20260928 当天有 4 场录到的是**静止画面**
(`a006` 58 帧/1 种、`201808_a3ab` 597 帧/11 种、`202928_3d8f` 387 帧/16 种、
`203642_816f` 599 帧/8 种)。⚠️ 使用者解释**其中几场是"被采集者不同意录制"**
—— 但注意:那几场的 `camera.webm` **只有 10–15 秒**(录像时长 ≠ 采集时长),
所以"画面不动"与"录像被截断"是**两件事**,后者仍未解释。③ 仍未修。

### 8.2.3 事故之后定下的操作守则(不改代码就能避坑)

1. **停止录制 → 必须看到「✅ 本场已留存」(标注 + sid + XX MB)→ 才刷新页面。**
   没看到就等于没存下。这一条能救回当天那场 7.3 分钟的录像(`20260928_200830_b82e`)。
2. **一次只开一个 `/analysis` 页面**;换学生用**新的一场**(现在每次「开始录制」
   会自动铸新号,不再需要手动 F5)。
3. **摄像头被占用/被拔会静默降级** —— 录之前先看预览动不动。

### 8.2.4 顺手查清的几件事

* **9/28 一份报告都没生成** —— 不是丢了,是**报告不自动生成**(要手动跑
  `report_generator` 或点面板按钮)。`data/output` 里最新的是 09-27 21:14。
* **14 场"0 帧无视频"的场次不是空壳** —— 每场都有一个 `transcript.json`,
  里面是**真的转写原句**(如 `20260924_220729_07d7` 有 12 段自我介绍)。
  尺寸成对相同(4035×6、48925×2)= 同一段音频被试跑多遍。**别按"看着像空壳"删。**
* **摄像头静止帧的检查脚本**(逐帧 md5 找连续重复)已在 §8.2.5 给出。
  ⚠️ **采样写法有坑**:`awk -v s=$step 'NR % s == 1'` 在 `s=1` 时**一个样本都取不到**
  (`NR % 1` 恒为 0),而它会把"0 个样本"静默判成"全部重复" —— 我用它误报了 5 场。
  **用 `NR % s == 0`**。

### 8.2.5 两个可复用的命令片段

**A. 判断某一场的画面有没有卡住**(逐帧 md5,gap > 60 秒算断开):

```bash
D=~/JingXin/recordings/<场次目录>
find "$D/media/face" -name '*.jpg' -printf '%T@ %p\n' | sort -n | awk '{print $2}' \
  | while read f; do md5sum "$f"; done | awk '{print $1}' | python3 -c "
import sys
h=[l.strip() for l in sys.stdin if l.strip()]
runs=[]; s=0
for i in range(1,len(h)):
    if h[i]!=h[i-1]: runs.append((s,i-1)); s=i
runs.append((s,len(h)-1))
dup=[(a,b) for a,b in runs if b>a]
print('共 %d 帧,%d 种画面' % (len(h), len(runs)))
for a,b in dup: print('  第 %d–%d 帧(%d 帧)是同一张图' % (a+1,b+1,b-a+1))
```

**B. 抢救被覆盖的原生录像**(只在真要试的时候用;必须**先用 sudo**,且**不能把
读出来的东西写到同一个文件系统** —— `/tmp` 也在同一个 LVM 上,写了就等于再覆盖一次。
写 `/dev/shm`(内存盘)):

```bash
# ① 先算覆盖图:每次上传的块跨度,谁最后写的那一段就是谁残留的尾巴
python3 - <<'PY'
import json, math, datetime
D = "<场次目录>"
rows = [json.loads(l) for l in open(D + "/retention.camera.jsonl")]
sizes = [r["bytes"] for r in rows]
maxblk = math.ceil(max(sizes) / 4096); owner = [None] * maxblk
for i, s in enumerate(sizes):
    for b in range(math.ceil(s / 4096)): owner[b] = i
segs = []; start = 0
for b in range(1, maxblk):
    if owner[b] != owner[b-1]: segs.append((start, b-1, owner[b-1])); start = b
segs.append((start, maxblk-1, owner[maxblk-1]))
cur = math.ceil(sizes[-1] / 4096)
print("当前文件占块 0..%d;之后的块按最后写入者:" % (cur-1))
for a, b, o in segs:
    if b < cur: continue
    t = datetime.datetime.fromtimestamp(rows[o]["received_at_wall"]).strftime("%H:%M:%S")
    print("  块 %6d..%6d (%7.1f MB) ← 第 %d 次上传(%s)" % (a, b, (b-a+1)*4096/1048576, o+1, t))
PY
# ② filefrag 拿到当前文件的**物理**起始块,才能换算成 dd 的 skip
filefrag -v "<场次目录>/media/camera.webm" | head -5
# ③ 只读探测(写进内存盘!)
sudo dd if=/dev/mapper/ubuntu--vg-ubuntu--lv bs=4096 skip=<起始块+已占块数> count=<跨度> of=/dev/shm/p.bin status=none
python3 -c "
d=open('/dev/shm/p.bin','rb').read()
print('实读 %.0f MB' % (len(d)/1048576))
for n,p in [('WebM Cluster',b'\x1f\x43\xb6\x75'),('JPEG 帧头',b'\xff\xd8\xff')]:
    print('  %-14s %d' % (n, d.count(p)))
"
# Cluster 几千个 + JPEG 很少 ⟹ 残片还在;JPEG 几千个 ⟹ 已被帧的写入用掉
```

**当前那两场的残留区间**(2026-09-28 实测算出来的,可直接用):
`20260928_180131_8102` 当前文件占物理块 `278867968..278901317`,残片区从 `278901318` 起;
`20260928_172642_1320` 当前占 `277823488..277826892`,残片区从 `277826893` 起。
