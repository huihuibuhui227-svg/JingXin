## 2. 挡在 T7 前面的硬伤:两个 CV 服务都死了

**这是本轮新发现,原文档只提了 gesture,把 face 当成可用的 —— 那是错的。**

| 服务 | 状态 | 坏法 |
|---|---|---|
| `-m voice_interaction.api.app`(:8001) | ✅ 能跑 | — |
| `-m face_expression.api.app`(:8000) | ❌ **每个 `/analyze` 静默 500** | `VideoPipeline.face_mesh` 是**惰性属性**(`pipeline/video_pipeline.py:33-41`),启动不碰它 → 服务"起来了"、`/health` 正常,第一帧才炸 |
| `-m gesture_analysis.api.app`(:8002) | ❌ **进程直接死** | `gesture_analysis/api/app.py:42-46` 在**模块导入期**取 `mp.solutions` → 连 uvicorn 都没绑上 |
| `-m report_frontend.report_generator` | ✅ 能跑 | — |

根因:`mediapipe 1.0.0` **整个 `solutions` 命名空间已删除**,只剩 `tasks`
(实测 `hasattr(mp,'solutions') → False`)。后果:`data/logs/` 里**永远不会出现**
`face_au_log_<sid>.csv`,**T7 的「face/voice 两份日志」判据在现环境不可能通过**。

**裁定:迁到 `tasks` API**(用户 2026-09-24 定)。三条路里选它而非"降到 mediapipe 0.10.x",
理由是干净、面向未来。**迁移的模型文件不随 pip 包发布**(实测 `find … -name "*.task"` 为空),
要单独下载。

### 修完之后才跑的 T7

**两个坑(不踩)**
1. **≥5 段回答,且内容各不相同** —— 同一段重复提交 → 每行密度相同 → `_std = 0` → **G2 按设计判
   「本次会话内无变化」**。G2 只要 ≥2 段;要**过门出分**还得满足 **G3 的样本量门槛 5**
   (每段回答一个样本,题库仅 8 题,默认的 10 不可达)。
2. **只能用 `/interview/start` 铸的 id** —— 自己编的 id 匹配不上报告侧的正则,报告里什么都看不到。

**另外一个环境缺口(不影响 T7):** TTS 是 `pyttsx3` → espeak → 靠系统 `aplay` 放音,而这个
WSL 里**没装 `aplay`**(`paplay`/`ffplay` 倒是在),所以交互式前端**听不见题**。
T7 用 curl 喂音频文件,不依赖它。

**核四条**
| 看什么 | 期望 |
|---|---|
| 落盘 | `ls ~/shared/jingxin_recordings/$SID/` → `session.json` + `transcript.json`(含逐字时间戳) |
| 对上号 | `data/logs/` 下 **face/voice/gesture 三份**日志文件名含 `$SID`、首列也是 `$SID` |
| 原句不出仓库 | 挑 transcript 里一句独特短语,`grep -rn "<短语>" ~/jingxin` → **0 命中** |
| 报告 | `~/miniconda3/envs/jingxin/bin/python -m report_frontend.report_generator` → 「**话语结构特征**」出现「**连接词密度**」行并**过门出分**;报告头出现「**数据来源**」并逐模态点名(I4);全篇**无分数与评级** |

## 4. 必须带进后续轮次的经验

1. **"测试通过 ≠ 有约束力"这一路反复出现**。形态:抽样唯一性断言、fixture 恰好 100 字导致分母
   可被删掉、空输入契约无守卫、`listen_for_speech` 的新规则是死代码、只认 query 的 id 会静默
   降级成 NONE、**断言用了裸词「不同」而报告别处本来就有「不同指标的量纲……」**(I4 收尾时我
   自己踩的)。
   - 强制动作:**每个测试都要能说出"哪个生产改动会让它变红、红得对不对"**;说不出来就是没约束力。
   - 已常驻:`tests/test_assert_coverage.py` —— 但**它抓不到"缺断言"**,别当万能。
2. **反向复现是标准动作**:写完后把生产改动撤掉(整文件回退 / 外科式抽掉接线),确认新测试
   真的红,再恢复。本轮 5 项逐项做过。
3. **变异验证必须清 `__pycache__`**:同一秒内"写入→跑→`git checkout` 还原"会**跑变异字节码**。
4. **阈值/常量一律进数据文件**(带 `_provisional` + 依据)。注意**单位错配**:门槛是给帧级列设的
   (一场上千帧),而「连接词密度」每段回答一个样本、题库仅 8 题 → 该族单独登记 **5**。
5. **跨任务集成点要在计划里点名**:T3 改文件名没把 `data_loader` 的选取正则列进改动面,导致报告
   路径什么都加载不到 —— 只有审查者用真加载器跑了一遍才发现。
6. **文档口径要一起改**:I3 就是"spec/计划说 ≥2 段、代码门槛是 5"这种互相矛盾,靠 grep 才抓得到。
   **但账本里的历史记录不改** —— 改了就成篡改。
7. **WSL 内删文件不还 Windows 磁盘**:`D:\WSL\ext4.vhdx` 只增不减,回收需 Windows 侧
   `wsl --manage <发行版> --set-sparse true` 或 diskpart compact。
