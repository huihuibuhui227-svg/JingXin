## 2. ★ 面部检出率崩塌(本次最重要的发现)

判据用 `tools/jx_check_session.py` 的那条(§8.4):**一行算"检出"= 除
`session_id`/`timestamp`/`timestamp_iso` 外还有非空值**。

| 检出率 | 场次数 |
|---|---|
| **0.0%(整场全空)** | **23** |
| 0.1% ~ 79% | 18 |
| **≥80%(过门槛)** | **8** |

**新旧素材都中招**,不是新素材独有:

| 日期 | 典型检出率 |
|---|---|
| 09-27 | 4.6% / 0.7% / 61.7% / 98.7% / 100% —— 好坏混杂 |
| 09-28 | 0.0% / 6.0% / 68.4% / 96.7% / 85.0% |
| **09-29(新素材)** | **0.0% × 8 场**,另 73.3% / 29.9% / 0.9% 各一 |

行数**是有的**(例如姬欣怡那场 444 行),但**行内 92 列几乎全空** ——
也就是说帧循环跑了、落盘了,而**面部特征一个都没算出来**。

⟹ **后果**:报告层所有面部派生槽(以及 L0 的面部列)对这 23 场是空的。
**任何拿面部特征做的标定,可用场次只有 8 场,不是 44 场。**

复核:

```bash
~/anaconda3/envs/jingxin/bin/python - <<'PY'
import csv, glob, os
skip = {'session_id', 'timestamp', 'timestamp_iso'}
for p in sorted(glob.glob('data/logs/face_au_log_*.csv')):
    rows = list(csv.DictReader(open(p, encoding='utf-8')))
    if not rows:
        continue
    det = sum(1 for r in rows
              if any(v not in (None, '', 'None') for k, v in r.items() if k not in skip))
    print(f"{os.path.basename(p)[13:-4]:34} {det:5}/{len(rows):5}  {100*det/len(rows):5.1f}%")
PY
```

### ★ 根因(2026-10-03 实测确定):**脸在画面里占的太小**

不是代码坏,也不是画面质量差。**把留存帧喂回同一个 `VideoPipeline` 逐帧重跑**:

| 场次 | 原测 | 未裁切重跑 | 中央裁切放大后重跑 |
|---|---|---|---|
| 姬欣怡 `..._040b` | 0% | **0 / 60** | **60 / 60(100%)** |
| 蔚欣辰 `..._b4a1` | 73% | 57 / 60(95%) | — |
| 洪思语 `..._f98d` | 85% | 18 / 60(30%) | — |

肉眼确认过:那 60 帧里人脸**清清楚楚、正面、光照良好**(1280×720,均值亮度 88.3)。
但 mediapipe 的**正面人脸检测器对"脸占画面的比例"敏感** —— 受试者坐得离摄像头远、
脸在画面里占比小时就检不到。**把画面中央裁掉一半(等于放大 2 倍)⟹ 立刻 100% 检出。**

> ⚠️ 这也解释了**为什么面部 0% 而手势 100%**:手势走 pose/hand 检测器,
> 在**半身尺度**上工作,对距离不敏感;面部走正面人脸检测器,对脸的大小敏感。
> **同一个机位,手能测、脸测不到,是正常的。**

**可用的补救**:跑面部提取前加一步**中央裁切/放大**(或换 mediapipe 的 full-range 检测器)。
留存帧本身完全够用,不必重录。

> ⚠️ 顺带纠一个我自己踩的坑:第一次重跑时我用"特征字典非空"当检出判据,
> 于是 `emotion='no_face'` 也被算成"检出",得出假的 100%。
> **正确判据是 `emotion != 'no_face'`** —— 这正是本仓在杀的"把没测到看成测到了"。

## 3. 语音日志为空 —— **符合预期,不是缺陷**

| 事实 | 数 |
|---|---|
| `session.json` 里声明 `logs.voice.expected=True` | 41 场(含 26 场新素材全部) |
| 语音日志 `interview_emotion_log_<sid>.csv` 有数据行 | **仅 4 个文件 / 24 行,全在 09-27** |
| 26 场新素材里有数据行 | **0** |

**根因(使用者 2026-10-03 澄清)**:新素材**不是机器问、面试者答**,
而是**老师面对面面试学生的完整自然过程**。所以:

- **`questions.jsonl` 结构上就不该有**(机器没提问,哪来的 `ask_end`)
- **`reaction_time` 定义上不存在** —— 它 = 首次开口墙钟 − 该题 `ask_end`;
  没有机器提问就没有这个基准。按本仓"不许编"的规矩**不得伪造**,该槽对新素材**永久不适用**
- 前端没往 `/interview/answer_audio` 提交音频 ⟹ 语音 logger 自然不写行

> ✅ `jx_check_session.py` 对这条**判得对**:它报的是
> 「语音行数 0 行 vs 答题 0 题」= **✓ 通过** —— 0 行对 0 题是自洽的。
> 所以这不是"被掩盖的失败",是**流程本身没有逐题结构**。
> `session.json` 里那句 `voice.expected=True` 对新流程是**过度声明**,可以改,
> 但它不影响判据。

## 4. 补救:从视频音轨走 ASR 采语言文本

26 场新素材**全都有视频**,视频**都带 opus 音轨**(实测),而 **FunASR 在
`0.0.0.0:10095` 正在监听** ⟹ 这条是拿到这批素材语言文本的唯一路径。

工具:`tools/jx_transcribe_recordings.py`(新增)

```bash
PY=~/anaconda3/envs/jingxin/bin/python
$PY tools/jx_transcribe_recordings.py --limit 1   # 试一场
$PY tools/jx_transcribe_recordings.py             # 全部(幂等)
```

实测:444.7 秒音频 → ASR 90 秒(**4.9x 实时**),1579 字,中英混说也认得出来。

**产出边界(工具里已显式声明,别误用)**:
- **会话级**转写,**不是逐题** —— 没有题目台账,切不出"第几题"
- **不产出 `reaction_time`** —— 见 §3,伪造它违反本仓第一原则
- **不做话者分离** —— 音轨里老师和学生都在,文本是**两人混合**的

> ⚠️ **隐私**:转写文本含真实受试者**姓名、成绩、家庭情况**。
> 产出落在 `data/transcripts/`,**已加进 `.gitignore`**(`**/data/transcripts/`)。
> 实测 `git check-ignore` 生效、`git status` 里看不到。**只留服务器,不进 GitHub。**

## 5. 顺带修掉的三个工具缺陷

`tools/jx_check_session.py` 此前**被路径漂移弄坏**,产出的是**假失败**:

| 缺陷 | 现象 | 修法 |
|---|---|---|
| `REC_ROOT` 写死 `~/shared/jingxin_recordings` | 只看得到 5 场旧素材,**26 场新素材完全在审计视野外** | 候选探测 `~/JingXin/recordings` → `~/shared/...` |
| `LOG_DIR` 写死 `~/jingxin` | 仓库实际在 `~/JingXin/jingxin` ⟹ 每场都报「收尾对账 跑不起来」 | 候选探测 |
| `PY` 写死 `~/miniconda3/...` | 本机实际是 `anaconda3` ⟹ 收尾对账恒失败 | 候选探测 |
| 拿**目录名**当 session_id | 新素材目录名是 `...-姬欣怡-...__20260929_195403_040b`,拼出的 CSV 名不存在 ⟹ **有 face 日志也报「日志 0 行」** | 读 `label.json` 的 `session_id`,退回按 `__` 切 |

这是本仓**第三次**踩"路径写死→换机器就坏"(`jx_env.sh`、`start_all.sh`、此处)
⟹ 一律候举探测,可用 `JX_RECORDINGS` / `JX_REPO` / `JX_PY` 覆盖。

> 教训和 `docs/下一步.md` §二 第 8 条同族:**测试再硬,跑错了对象也一样。**
> 审计工具自己的路径漂移比不审计更坏 —— 它会给你一批看起来很像真的的假失败。
