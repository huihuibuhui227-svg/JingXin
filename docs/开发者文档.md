## 0. 先读这一节:这个系统是什么,不是什么

**是**:一套**结构化行为记录**系统。它把一场面试里受试者的面部动作单元、手部/姿态、
语音韵律、话语结构采下来,落成逐帧/逐回答的 CSV,再在报告层按一套有出处的判据
**给出一份「哪些行为线索有足够证据、哪些没有」的披露**。

**不是**心理测量工具,也**不做**心理识别结论。这条不是措辞偏好,是硬约束:

- 报告层**不渲染任何复合分、不给档位** —— 它自己写着「尚无标定样本,不同指标的量纲无法折算为同一尺度」。
- 判据/阈值**只能来自物理下限或自采数据**。上游数据集(RecruitView)的许可**禁止**把在它的
  分布上拟合出来的参数用于真实招聘/筛选/心理画像 —— **在数据集分布上拟合的参数(含 L1 阈值)同样属禁**。
- 采集自评量表**必须先过科技伦理审查**。这一条会拦住整个 L2 层。

所以:**完善系统本身**是主线,不是复现某篇论文。两者的取舍在冲突时以前者为准。

## 2. 整体结构

系统是**两个 git 仓 + 一个素材目录**,不是一个仓:

```
① ~/jingxin                    后端 / 采集 / 报告 / 面板   ← 本仓
② ~/JingXin-frontend           前端(React + Vite + TS)   ← 另一个仓
③ ~/shared/jingxin_recordings  录制素材(原始媒体,**故意不进 git**)
```

## 3. 逐层详解

### 3.1 采集层(三个 FastAPI 服务)

| 服务 | 入口 | 端口 | 落盘 |
|---|---|---|---|
| face | `face_expression/api/app.py` | 8000 | `data/logs/face_au_log_<sid>.csv` |
| voice | `voice_interaction/api/app.py` | 8001 | `data/logs/{interview,research}_emotion_log_<sid>.csv` + `assessment_note_*.csv` |
| gesture | `gesture_analysis/api/app.py` | 8002 | `data/logs/gesture_emotion_log_<sid>.csv` |

**每个服务的内部管线**:

- **face**:`pipeline/video_pipeline.py` → `core/feature_extraction/au_calculator.py`(AU 与几何)
  + `core/analysis/{emotion_engine,tension_engine,micro_expression}.py`;
  `models/blendshapes.py` 是 52 个 `bs_*` 名字的**单一真源**。
- **gesture**:`core/detectors.py` → `core/analysis/{hand,arm,shoulder,upper_body}_analyzer.py`
  + `core/analysis/jitter.py`(抖动公式只有一份,四个 analyzer 共用)
  + `core/feature_extraction/angles.py`(手指/姿态角度,2026-09-26 从 `examples/` 移植进活路径)。
  可复用入口:`gesture_analysis/api/app.py::process_frame`(被 `experiments/replay_retained.py` 调)。
- **voice**:`api/app.py` → `core/feature_extraction/prosody_extractor.py`
  + `core/analysis/prosody_analyzer.py` + `asr/{funasr_engine,transcribe,connective_density,transcript_store}.py`。

**改一列时要动的地方**(顺序别反):
1. logger 的 `fieldnames`(列名契约的**唯一声明处**)
2. 产出方(分析器/提取器)
3. `l0_columns.json` 对应行(`definition` / `source` / `normalization` / `unit` /
   `acceptance`;`status` 一般不动)
4. 跑 `pytest`:`test_l0_column_table.py` 会在你只改了一头时**变红**。

### 3.2 留存与元数据层(仓库根横切)

| 文件 | 干什么 |
|---|---|
| `media_retention.py` | 把**收到的字节原样**存到仓库外。落点 `~/shared/jingxin_recordings/<sid>/media/`,账本 `retention*.jsonl` |
| `session_purge.py` | 把**一场**从盘上抹掉(「不留存 / 不同意」那条路)。删**四处**:场次目录、`data/logs/` 里按 sid 落盘的 CSV、`data/output/` 里**正文点名了这个 sid** 的报告及其独占图表、`data/l0_series/<sid>.npz`。**没有回收站**,是刻意的 |
| `session_meta.py` | 阶段 A 元数据:`meta.json` 模板 / 校验 + 逐题时刻 `questions.jsonl`。CLI:`python -m session_meta --write-template/--check-session` |
| `session_clock.py` | 会话相对时钟,保证 ms **严格递增**(mediapipe `VIDEO` 模式的要求) |
| `logging_config.py` | 统一日志 |

**为什么留存层单独存在**:分析代码必然有缺陷,而缺陷一旦作用在「算完就扔」的流水线上,
就被**永久烘进数据**、事后无法重抽。有了原始媒体,任何时候都能拿新代码重放同一批帧。

⚠️ **重放必须喂留存账本里的 `declared_ts`**,不能用墙钟 —— 用墙钟会得出「推理不可复现」的
**假**结论(landmarker 是 `VIDEO` 模式,时间戳是模型输入)。样板:`experiments/replay_retained.py`。

### 3.3 报告层 `report_frontend/`

| 文件 | 职责 |
|---|---|
| `data_loader.py` | 按 `session_id` 取每个模态的日志(批处理读盘 / 实时走 HTTP `/summary`) |
| `feature_engine.py` | CSV → 扁平特征字典;每个数值列展开成统计量 |
| `research_mapper.py` | 14 个槽 → 关键词匹配 → 证据门(**对照用的旧引擎**;生产默认 `l1_mapper`) |
| `evidence_gate.py` | **G1–G4 四关** + 封停名单 |
| `evidence_thresholds.json` | 阈值与满量程(每条带依据) |
| `visualizer.py` / `report_generator.py` | 图表与 HTML 报告 |

**G1–G4 是什么**:四道闸,一道不过就**不出分**,并在报告里如实说明为什么。
⚠️ 四关全都只看**原始列**。这也是 2026-10-04 把**折算层**(`normalize_value` /
`scale_factor_for` / `evidence_thresholds.json` 里的 `scale_factors`)整层删掉的原因之一:
一份"折算因子选错 ⟹ 造出恒定量槽、而四关全放行"的风险,不值得用一层没人复核的
满量程换算去换(`jitter`、`reaction_time` 都是这么漏过去的,见 §8)。
现在阈值文件只有 `thresholds` / `n_valid_units` / `_default_n_valid`。

### 3.4 面板与前端

- 面板 `app.py`(Flask,:5000):报告列表 / 打开报告 / 起模块任务。它用
  `subprocess` 起 `python -m report_frontend.<module>`。
- 前端 `~/JingXin-frontend`(**另一个仓**):`src/services/api.ts` 是**唯一的后端契约点**。
  `session_id` 的生命周期也在那里(服务端铸号,前端只存)。

### 3.5 权威层 `l0_columns.json`

86 行,每行一个字段:`column` / `modality` / `definition` / `source` / `normalization` /
`unit` / `maturity` / `l0_output` / `status` / `quarantine_ref` / `acceptance`。

两个轴:
- **`status`**:`implemented` / `l0_done` / `pending` / `blocked`。
  - `l0_done` = L0 侧口径**已落地并实测**,但验收里还有一条**只能来自标定集**的子项(故不标 `implemented`)。
  - `blocked` = 卡外部条件,**必须**在 `acceptance` 里写「解封条件」。
- **`maturity`**:`A` / `B` / `C`,语义判据在
  `docs/superpowers/specs/2026-09-26-l0-column-table-design.md` §4.2(**不在 JSON 里** —— JSON 只校验字母合法)。

另有一个 `legacy_allowlist`:「确定不要的既有列」,每条带 `why` + `planned`。

## 4. 数据契约:一列从产生到消费

一列要能进报告,得**三处对齐**。本仓栽过的所有「静默的零值」都是这三处里有一处没对齐:

```
① 生产方           ② 列名契约            ③ 消费方
分析器算出值   →   logger.fieldnames   →   feature_engine / research_mapper 的关键词
```

**三类事故(都真实发生过)**:

1. **上游产出名 ≠ 下游列名** —— 提取器吐 `pitch_std`,而日志列叫 `pitch_variation`,
   改名只发生在一个中间类里 ⟹ 那两列**安静地留 0**,其余每列都对。
   → 接线时**逐个键对一遍**,并钉一条**只守改名**的测试。
2. **生产方改了单位/口径,消费方没改** —— iris 四列改成「眼内相对坐标」(以 0 为中心),
   而消费方仍按 `sqrt((x−0.5)²+(y−0.5)²)` 算「到**画面中心**的距离」。
   → **核了生产方不等于核了消费方。**
3. **消费方用关键词子串匹配** —— `research_mapper` 按子串找列,而
   `evidence_gate` 的封停也是子串匹配(`head_tilt` 是 `head_tilt_angle` 的子串)。
   → 加列/改名时,子串匹配会**静默命中或漏掉**。

## 5. 会话与 ID 的生命周期

`session_id` 的形态是 `YYYYMMDD_HHMMSS_xxxx`,**由服务端铸**(`/interview/start`)。

- 前端 `api.ts` 持有它,给 face/gesture/voice 三路共用。
- 没带 id 的请求落进 **`NONE` 桶**(`*_log_NONE*.csv`)。报告头会**点名** NONE 桶有多少行,
  并说明那些不属于本场 —— 这是刻意的,不许静默混入。
- 报告侧只认**服务端铸号的形态**;前端自己造 UUID 的话,日志文件名匹配不上正则,
  报告端根本看不到它们。

## 7. 测试与「钉子」

套件在 `tests/`(111 个模块)。**本仓对测试的要求比「通过」高一档**:

> **每个测试都要能说出「哪个生产改动会让它变红、红得对不对」。说不出来就是没约束力。**

所以本仓的测试大多带一段 `★ 红法:` docstring —— 那不是装饰,是这条测试的**存在理由**。
新增钉子时照这个格式写。

现有的几颗关键钉子:

| 钉子 | 钉住 |
|---|---|
| `test_l0_column_table.py::test_every_live_column_is_either_in_the_table_or_allowlisted` | 双向覆盖:每条活列要么在表里、要么在白名单里 |
| `…::test_live_contract_matches_the_real_log_contract` | `l0_columns.json` 的 `live_contract` 与三个 logger 的**实测** `fieldnames` 条数一致 |
| `…::test_the_table_carries_no_line_number_references` | 表里**不许出现** `*.py:NN`(行号会静默失效) |
| `test_l0_reference_paths.py` | 表里的文件引用必须解析到**唯一**文件 + 行号在界内 |
| `test_assert_coverage.py` | 断言覆盖率(**它抓不到「缺断言」**,别当万能) |
| `test_log_isolation.py` | 测试不许往仓库 `data/logs/` 写文件 |
| `test_emotion_threshold_staleness.py` | AST 双向比对:源码里的门限常量 ↔ 账本 |
| `test_gesture_dead_code_removed.py` | `gesture_analysis.__all__` 里不许有悬空名字 |

**跑法**:`JX_RUN_MUTATIONS=1 <本仓 python> -m pytest -q`
(解释器按机器解析,见 §11.1;没带那个变量时「变异实测」会被跳过,而覆盖率守卫会**照实**报 1 红 —— 详见 §8「已知陷阱」。)
(需要 `pip install -r requirements-dev.txt` —— `pytest` **不在** `requirements.txt` 里)。

**没装 pytest 时怎么看出来**:会直接报 `No module named pytest`。别把它当成"环境没建好"。

## 8. 已知陷阱清单(踩过的,别再踩)

1. **说「验证过」之前先问:我跑的这条会不会执行到我要证的那段代码?**
   - 合并门 `0/2835510` 对**采集层**的改动**结构上不可见**(它读的是盘上静态 CSV,不 import 被改代码)。
   - **只核清单 ≠ 验证**;**核了生产方没核消费方 = 没核**。
2. **散文里的数会静默过期**。数只说一次;能算的就别手写。
   本仓为此把结构图改成脚本生成(`tools/jx_inventory.py`)。
3. **重放必须喂 `declared_ts`**,用墙钟会得出「推理不可复现」的**假**结论。
4. **不许编阈值/常量**。没有标定集(仪器标定已裁定跳过)⟹ 做不到就如实说做不到。
5. **内嵌的源码副本会静默分叉**。文档里别抄代码,写**符号名**。
6. **被推翻的「现状」被抄进源码注释之后,`grep` 就再也查不出它** ——
   `media_retention.py` 的文档字符串至今写着「全仓无 `VideoWriter`」,而全仓 `grep VideoWriter`
   的**唯一命中就是这句话自己**。注释只写「这个模块做什么」,别写「为什么需要它」的现状清点。
7. **`git status` 在前端仓会假阳性**(mtime 变了、内容与 HEAD 逐字节相同)。
   别按 status 数数,用 `git diff --numstat` 或 `hash-object` 核。
8. **提交前先点名「哪些文件里装着别人的未提交工作」**。git 按文件暂存,
   一个文件里同时有你的改动和他人的 WIP 时,`git add <文件>` 会把 WIP 一起带上。
9. **别用 `git add -A`**。本仓有未跟踪的论文线(`experiments/`)与冻结的复现包
   (`code_data_supplement/`)。逐路径点名。
10. **WSL 内删文件不还 Windows 磁盘**(`ext4.vhdx` 只增不减)。
11. **服务必须 `setsid` 起**,否则终端一 Ctrl-Z 就成 T 态(端口在听却不回话,看着像崩溃),
    且收不到 TERM「杀不掉」。`tools/start_all.sh` 已经这么做了。
12. **两条验收脚本有已知卡死点**(`m2_acceptance.sh`):`start_all.sh` 等 `npm run dev` 的子进程;
    第⑤步 `webbrowser.open` 的管道 grep 等不到 EOF。**先单独把 `start_all.sh` 跑完**,再跑它。

### 10.3 语音那一路:FunASR 怎么办

**这是唯一需要你决策的一块。** 端点配在 **一个文件里**:

`voice_interaction/asr/asr_config.json` 的 `funasr_host` / `funasr_port`(默认 `192.168.72.30:10095`)。

三条路,按代价排:

| 路 | 做法 | 代价 |
|---|---|---|
| **A. 让对方网络里也有一台 FunASR** | 照官方 `runtime` 镜像部署,然后改 `asr_config.json` 的两行 | 需要一台能跑 FunASR 的机器(它不轻) |
| **B. 把现有那台暴露出去** | 端口转发 / VPN | 取决于你们的网络,且涉及把内网服务开出去 |
| **C. 换成别的 ASR** | `voice_interaction/asr/` 是适配层,`funasr_engine.py` 是引擎封装 | 要写一个新引擎 + 满足 §4 的契约(逐字时间戳、`raw['timestamp']`),有真实工作量 |

⚠️ 不管走哪条,`AsrUtterance` 的契约要满足:**逐字毫秒时间戳**在 `raw['timestamp']` 里。
连接词密度只依赖**文本**,但语速/停顿/反应潜伏期依赖时间戳。

**没有 ASR 会怎样**:语音那条链断,`speech_ratio` / `pitch_variation` / `pause_*` / `n_chars` /
`reaction_time` / 连接词密度**全部拿不到**;face 与 gesture 两路**不受影响**。
报告仍能出,只是语音相关的槽会如实显示「未采集到对应数据」。

### 10.4 部署到服务器 + 常驻 + 从别的电脑访问

**一个容易踩的坑先说**:前端的后端地址默认**按页面的 host 推断**(见前端仓
`src/utils/constants.ts`)。所以「从别的电脑打开网页」时,那个电脑的 `localhost`
指的是**它自己** —— 你必须用**服务器的地址**打开页面:

```
✗ 在那台电脑上开 http://localhost:5173      ← 找的是它自己
✓ 开 http://<服务器IP>:5173                 ← 后端也跟着指向服务器
```

**三样东西必须同时到位**,少一样远端就连不上,而且症状各不相同:

| # | 要什么 | 少了的症状 | 怎么给 |
|---|---|---|---|
| 1 | 前端绑 `0.0.0.0` | 那台电脑根本打不开页面 | `JX_BIND=0.0.0.0`(见下) |
| 2 | 面板绑 `0.0.0.0` | 页面能开,但报告列表/结构接口全失败 | 同上(自动设 `PANEL_HOST`) |
| 3 | **CORS 放行页面 Origin** | 页面能开,**浏览器控制台一片 CORS 报错,而服务端日志显示请求根本没到** | 同上(自动把本机所有 IP 加进 `CORS_ORIGINS`) |

三个 FastAPI 服务默认已经绑 `0.0.0.0`,不用管。

**临时起(前台):**

```bash
cd ~/JingXin/jingxin
JX_BIND=0.0.0.0 JX_PY=~/anaconda3/envs/jingxin/bin/python \
JX_RECORDINGS=~/JingXin/recordings JX_FRONTEND=~/JingXin/frontend \
  bash tools/start_all.sh
```

**常驻(推荐):装成 systemd 用户服务** —— 照这台机器上 FunASR 的做法
(`~/.config/systemd/user/funasr-streaming.service`,已连跑 5 天)。
比 `setsid` 强的地方:**重启机器也会自动起**。

```bash
cd ~/JingXin/jingxin
bash tools/systemd/install.sh --dry     # 先看会写什么
bash tools/systemd/install.sh           # 装 + 起 + 开机自启

sudo loginctl enable-linger $USER       # ★ 只做一次;不开的话你退出登录后服务会被回收

systemctl --user status  jingxin-voice  # 看状态
journalctl --user -u jingxin-voice -f   # 看日志
```

`install.sh` 会自动探测:仓库路径、解释器、素材目录、前端目录、**node 的位置**
(systemd 的 PATH 很干净,nvm 装的 node 不显式给就找不到),以及**本机所有 IP**
并写进 CORS。

⚠️ 用**所有** IP 而不是第一个:`hostname -I | awk '{print $1}'` 在多网卡机器上
可能取到 Tailscale/VPN 那个,于是真正用来访问的 LAN IP 反而没放行(实测踩到)。

### 10.5 ★ 从别的电脑录制:**必须走 SSH 隧道,不能直接开 IP**

**这是「部署到服务器」这件事上最容易踩、也最贵的一脚。**

浏览器规定:`getUserMedia` / `navigator.mediaDevices` **只在「安全上下文」里存在**,
也就是 `https://` 或 `http://localhost`。**`http://<任何IP>` 两者都不占** ⟹
`navigator.mediaDevices === undefined` ⟹ **摄像头和麦克风在 JS 层面就不存在**。

2026-09-27 在同一台机器、同一个页面上实测,**只换地址**:

| | `http://192.168.72.30:5173` | `http://localhost:5173`(走隧道) |
|---|---|---|
| `window.isSecureContext` | **False** | **True** |
| `typeof navigator.mediaDevices` | **undefined** | **object** |
| `typeof navigator.mediaDevices.getUserMedia` | **undefined** | **function** |
| 实际取流 | 报 `Cannot read properties of undefined` | ✅ `video:1 轨 audio:1 轨`,真设备 `Integrated Camera (04f2:b7b8)` |

**这不是配置问题,没有开关可开。** 三条路:

| 路 | 代价 |
|---|---|
| **① SSH 隧道**(`tools/tunnel_to_server.sh`) | 零证书、零服务端改动;每台客户端跑一条命令;`http://localhost:5173` 本来就在 CORS 白名单里 |
| ② 上 HTTPS | 自签证书要每台客户端接受一次;**且五个服务全得 HTTPS** —— 否则页面是 https 而接口是 http,混合内容会被浏览器拦 |
| ③ 浏览器跑在服务器上 | 服务器没摄像头,不成立 |

**推荐 ①。** 它顺带解决第二件事:隧道**只需要 22 端口可达**,
8000/8001/8002/5000/5173 一个都不用对外开。

**从外面(不在同一局域网)录制**:那几台电脑要能 ssh 到服务器 ——
本仓不做网络方案,由你定(实测:本机的 Windows Tailscale 与服务器**不在同一个 tailnet**)。

```bash
# 客户端(要录制的那台电脑):
bash tools/tunnel_to_server.sh          # 默认 zgy@192.168.72.30
JX_SERVER=zgy@<可达地址> bash tools/tunnel_to_server.sh
# 浏览器打开:
http://localhost:5173                   # ★ 必须是 localhost,不是 IP
```

⚠️ 第一次打开浏览器会**弹摄像头/麦克风授权**,要点允许。自动化验证时我用 CDP 的
`Browser.grantPermissions` 跳过了这一步;真人操作时会看到那个弹窗。

### 10.6 换机器后要复验的三件事

1. **三个 `.task` 都能被加载** —— 起服务时若模型缺失,face/gesture 会**在启动期**拦住你
   (这是 M1.5 特意加的 `verify_models`,别绕过)。
2. **`bash tools/m26_media_acceptance.sh`** —— 无外部样本依赖,起完就能跑。
3. **`JX_RUN_MUTATIONS=1 pytest -q` 全绿** —— 若有红,先对照下面这张「报错 → 真因」表:

   | 报错 | 真因 | 修 |
   |---|---|---|
   | `No module named pytest` | `pytest` 不在 `requirements.txt` | `pip install -r requirements-dev.txt` |
   | `OSError: PortAudio library not found` | 缺**系统库** `libportaudio2` | `sudo apt install libportaudio2` |
   | `requires the httpx2 package` | `httpx2`/`httpx` 都没装 | `pip install -r requirements-dev.txt` |
   | `test_no_assert_is_dead` 报「从未进入 call 阶段」 | 裸跑没设 `JX_RUN_MUTATIONS=1`,变异实测被跳过 | 加上变量重跑。**这不是代码缺陷**:那条闸在照实说"跳过的测试没被核实过" |

   ⚠️ `requirements.txt` 用的是**全开区间**(如 `fastapi>=0.68.0`)⟹ **两台机器会装出
   不同版本**。2026-09-27 实测:本地 starlette 1.4.1、服务器 1.7.0。这次没有造成故障
   (两者的 `testclient` 兜底逻辑逐行相同),但**这是「在我机器上能跑」的结构性隐患** ——
   要真正可复现,需要一个锁版本文件。**目前没有,如实记。**

跑 `bash tools/m2_acceptance.sh` / `t7_acceptance.sh` 还需要**素材**:它们要「一张真脸 /
一只手 / 几段真人语音」。默认从 `$JX_RECORDINGS` 下最近一场**真有素材**的会话里取;
没有素材就显式给:

```bash
JX_FACE_FRAME=/path/face.jpg JX_GESTURE_FRAME=/path/hand.jpg \
JX_AUDIO_SAMPLES="/path/a.wav /path/b.wav ..." bash tools/m2_acceptance.sh
```

### 10.7 ★ 换一台电脑开发(以 Mac 为例):**本地不部署整套**

**一句话**:后端整套留在服务器上,那台电脑**只跑前端**。Python、mediapipe 模型、
FunASR、素材目录**一个都不用装、不用拷**。

#### 先记住这一条 —— 摄像头**只在安全上下文里存在**

| 浏览器开的是 | 是安全上下文吗 | 摄像头 |
|---|---|---|
| `https://gpuserver.tail4ffce2.ts.net:5173` | ✅ | 能用 |
| `http://localhost:5173` | ✅ | 能用 |
| `http://192.168.72.30:5173` | ❌ | **在 JS 层面就不存在**(`navigator.mediaDevices === undefined`) |

⚠️ 而且四个后端服务**都已经改绑 `127.0.0.1`**(§5-②),所以从别的电脑**直连
`192.168.72.30:8001` 是连不上的**。只有两条路:`tailscale serve` 的 https,或 SSH 隧道。
这一脚是本仓最贵的,见 §10.5。

#### 两种姿势,选一种

**A. 前端也跑在服务器上**(最省事;改代码要同步上去)
```bash
# 浏览器直接开:
https://gpuserver.tail4ffce2.ts.net:5173
# 改完把 src/ rsync 上去,服务器上那个 Vite 会自己 HMR
```

**B. 前端跑在本地**(改代码最快,**推荐给"主要改前端"的时候**)
```bash
# ① 把服务器的后端端口接到本地(注意:**别转 5173**,本地那个端口要留给自己的 Vite)
ssh -N -L 5000:localhost:5000 -L 8000:localhost:8000 \
       -L 8001:localhost:8001 -L 8002:localhost:8002 \
       zgy@192.168.72.30

# ② 本地起前端
git clone git@github.com:huihuibuhui227-svg/JingXin-frontend.git ~/JingXin-frontend
cd ~/JingXin-frontend && npm install && npm run dev
#   → 打开 http://localhost:5173
```

为什么这样就通:`src/utils/constants.ts` 是**按页面的 host 推断**后端地址的 ——
页面在 `localhost` ⟹ 接口打 `localhost:8001` ⟹ 正好落到隧道上 ⟹ 到服务器。
**页面是 localhost ⟹ 安全上下文 ⟹ 摄像头可用。**

> 服务器上那个 5173 的 Vite 仍在跑(systemd)。两边各开各的,不冲突 ——
> 只是**别把隧道的 5173 也转了**,否则本地端口被占,自己的 Vite 起不来。
> 后端不在本机时也可以不用隧道,改成显式给地址(`VITE_VOICE_API_URL=…` 等,
> 见 `constants.ts` 顶部),但那条路要注意 CORS 白名单得放行页面的 Origin。

#### 那台电脑上要装什么

| | |
|---|---|
| node + npm | 要(前端)。版本尽量与服务器对齐,`nvm` 装就行 |
