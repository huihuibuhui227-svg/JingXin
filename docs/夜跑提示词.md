## B. 昨夜踩过的坑(十七条硬约束)

每条都是真实事故,不是理论风险。写进提示词时**照抄,别概括**。

### B-1 开工第一步先提交

服务器上**真正的活工作曾经全在未提交工作区** —— 883 行改动 + 67 个未跟踪文件,
其中 M4 L1 指标层 15 个模块约 4,228 行全是 `??`,而 `app.py` 已经默认调用它们。
**一次 `git clean -fd` 就全没了。**

⟹ 开工第一件事:`git status --short` 看一眼。**有改动就先提交**,哪怕提交信息写得糙。

### B-2 判绿要串行跑

**别同时开两个全量门。** 2026-10-24 实测并行跑两份,冒出 2 条偶发红
(`test_media_retention_voice::test_research_answer_audio_is_retained`、
`test_prosody_wiring::test_extraction_runs_off_the_event_loop`),**单跑都是绿的**。

根因是 `--basetemp` 互删:`test_mutation_registry._run_one` 的子进程 pytest
用默认 temp 根,而 pytest 只保留最近 3 个编号,于是**删掉父进程正在用的那个**。
`test_mutation_registry.py:322` 的注释里早就记过这个洞。

⟹ 门要**串行跑一次**才算绿。看到偶发红先问"是不是两个门在打架",别急着归成 flake。

### B-3 跨机拷贝后先清 `__pycache__`

服务器上曾有 **68 个 `.pyc` 烧着本机路径** `/home/huihuibuhui/jingxin/...`。
Python 按**源码 mtime + size** 判定陈旧,**路径不同照样命中** ⟹ `sys.settrace`
读到的 `co_filename` 是本机路径,与被扫描模块的 abspath 对不上,覆盖率守卫于是报
**几百条「assert 从未执行」的假红**。

**症状极具误导性**:内层套件全绿、单跑插件也正常,只有按它自己路径过滤时全空。

    # 判据
    grep -rl "/home/huihuibuhui" --include="*.pyc" tests/
    # 修法
    find . -name __pycache__ -prune -exec rm -rf {} +

⟹ **任何跨机拷贝之后,先清 pycache 再判绿。**

### B-4 量素材前先设 `JINGXIN_RECORDINGS_DIR`

服务器上 `~/shared/jingxin_recordings` **存在但基本是空壳**(只剩 4 场旧试跑 +
41 个空目录)。真素材 9.9 G 在 `~/JingXin/recordings`。

同一台机器、同一份盘、同一份代码:

    corpus.audit_corpus()  不带环境变量 → 「45 场 / 正式场 0」
    corpus.audit_corpus()  带上         → 「41 场 / 正式场 24」

**两个数都"算对了",但说的不是同一件事。** 生产代码 `media_retention.root()`
现在按「环境变量 → `~/JingXin/recordings` → `DEFAULT_ROOT`」的顺序探,
但**手工跑探针/脚本前仍然先设**:

    export JINGXIN_RECORDINGS_DIR=~/JingXin/recordings
    # 或者用 tools/jx_env.sh,它已经处理好

### B-5 PII 扫描要两条腿

本仓 GitHub 远端是**公开仓库**。扫描必须两条腿,少一条都会漏:

1. **`姓名+学号` 正则**:`[一-龥]{2,4}[-_][0-9]{9,10}`
2. **姓名池全文扫**:从录制目录名里取出姓名池,再全仓全文找

**第一条漏得掉**只出现姓名、不带学号的地方 —— 2026-10-24 就是这样漏了 14 处,
是另写扫描器才发现的。

⚠️ 扫描器要认得脱敏占位符(`候选甲-000000000`),否则会把占位符报成命中。
⚠️ **扫描结果只输出行数,不要打印匹配行** —— 打印出来就等于把 PII 又写进了会话记录。

### B-6 验证前先问:「我跑的这条会不会执行到我要证的那段代码?」

这是本仓**最高频**的形态,2026-10-24 夜已经是**第 6 次**。

两个真实变体:

* **空转的守卫**:`test_l1_engine_payload_carries_no_scoring_keys` 走空数据端点,
  而空数据下 `dim["stats"]` 恒为 `{}` ⟹ `for stat in ...` 一次不进,
  那句 `assert "percentile" not in stat` **从上线起就没跑过**。
* **量错了对象(昨夜最新一次)**:直接 `build_l1_report(sid)` 不带 `logs`,
  实测**所有场都是 0 条有值** —— 因为 `compute_session_l1` 收到 `logs=None`
  就按"该模态缺失"处理,**不会自己去 `data/` 里找**。要走
  `LogDataLoader().get_fused_latest_data(sid)` 再传进去,才是
  `app.py:get_structured_report` 那条生产路径。

⟹ **说「验证过」之前,先指明验的是哪个产物、走的是哪条入口。**

### B-7 恒等式按代数验,不按回归验

`fluency_score` 那条裁定里,`voiced_sec / 停顿段数` **恒等于** `60 / pause_rate_per_min`。
我先算了一个「对三条回归 R²=0.863」的数,差点拿它当"86% 冗余"的依据 ——
**那个数不能用**:自变量里含 `pause_rate_per_min`,而因变量是它的倒数,
线性回归对非线性恒等本来就拟合不好(真值 1,回归给 0.863)。

⟹ **恒等式按代数验(看残差,实测 4.4e-16),不按回归验。** 回归 R² 只能证相关,
不能证恒等。

### B-8 配额 403 要能续

2026-10-24 **04:37** 被这条打断:

    API Error: 403 Subscription quota is insufficient ... need=119611

**停了 2 小时 23 分钟**,直到使用者 07:00 手动打了一句「继续跑」。

⟹ 这不是权限问题,是**中转站额度**。外壳脚本要能**等一段时间重试**,
且**重试不丢上下文**(用 `--resume` 或 `-c` 续上,别重开)。

### B-9 提交信息里的反引号会被 shell 吃掉

2026-10-24 实测:本地 shell 把提交信息里的反引号当成**命令替换**执行掉了,
正文丢了词。

⟹ **提交信息一律用文件传入**(`git commit -F /tmp/msg.txt`),
不要 `-m "..."` 里塞反引号。

### B-10 文档里的"待办诊断"也可能本身就是错的

2026-10-24 夜实测:`docs/开发者文档.md` §12.2 把 `assessment_note_*.csv` 记成
「文件名没 sid ⟹ purge 时留下孤儿」。**孤儿的前提是有内容,而它从来没有过内容** ——
当场复算:515 份、数据行 0 行、515 份**逐字节相同**。根因是 `save_log()` 的
prosody 门与活路径 `add_answer()` 不传 prosody 之间对不上,跟 sid 毫无关系。

⟹ **文档里的待办是线索,不是结论。** 动手前先**当场复算**那个数,并问一句
「这条描述的**因果**成立吗」。按错误诊断去修,会修一个不存在的问题
(给文件名加 sid 也照样是 515 个空文件)。

### B-11 假数据的"兜底"比崩溃更坏

同一夜:空日志时 `visualize.py` 拿 `np.random.seed(42)` 造的 10 行顶替真数据,
图照样画、照样存盘、照样 `return True`。⟹ 「这一场什么都没采到」被渲染成
一张看起来正常的多维分析图。**图比错误信息更可信**,所以危害更大。

⟹ 扫描时专找这个形态:**在"没有数据"的分支里 `return True` / 写文件 / 画图**。
兜底只许两种:① 明说没有、`return False`;② 报错。**不许造。**
判据写成"盘上没多出文件",不是"返回值是 False" —— 先造假再返回 False 会骗过只看返回值的断言。

### B-12 恒真断言:跑到了 ≠ 判据成立

同一夜扫 `tests/`,抓到两条**永远不会红**的断言(都已修):

    assert "左" not in reason or "可见性" in reason      # 理由里两个词都有 ⟹ 恒真
    assert real is Path.write_bytes or True              # 字面恒真

`test_assert_coverage.py` 抓不到它们 —— 它们**确实执行了**。
⟹ 写循环/条件断言时问:「**哪一次运行会让它红?**」答不出来就是恒真。
`or` 的两边若可能同时成立,这条断言什么都没守。

### B-13 守卫要守**生产路径**,不是对照路径

同一夜:`research_mapper`(旧引擎)有「同一份测量不许喂两个槽」的守卫,
而生产默认路径 `l1_mapper`(`/api/report/structured` 默认 `engine=l1`)**一条都没有**。
守着对照用的旧路径、跑着 L1 —— 这是 B-6 的孪生形态,且**静默**。

⟹ 新增/迁移引擎时,先列一张表:**旧路径有哪些守卫,新路径对应哪条**。
缺的当场补,别等下一轮。

### B-14 写完守卫必须**真跑一次变异**,别在注释里写"红法"就算数

同一夜,这一条自己咬了自己:给「每答一题不落产物」写端到端测试时,
注释里写着「红法:把 `save_log()` 加回端点 ⟹ 本条红」。**真去跑,8 passed。**
原因:`_write_note` 修好之后无数据行就不写文件,所以"加回调用"**不改变盘上状态** ——
那条断言("目录里没有 csv")根本没有区分力。

改法:把判据钉在**接线**上(monkeypatch 计数 `save_log` 的调用次数),而不是
只钉端状态。再跑一次变异 ⟹ 这次真红了。

⟹ **"红法"是断言,不是注释。** 写进 docstring 之前先跑一遍;
跑不红就说明这条测试测的不是你以为的那件事 —— 它是个假守卫。
(与 B-6 的区别:B-6 是"跑错了对象",这一条是"根本没验过它会红"。)

### B-15 架构数要钉成测试,不是抄进散文

同一夜文档审计**一次抓到 10 处过期**,最贵的三处:
`research_mapper` 写「20 个槽」(实为 **14**)、`evidence_gate` 写有折算层
(`normalize_value`,2026-10-04 **整层删除**)、套件写「74 个模块」(实为 **111**)。
形态与前 7 次一致:**旧小节里的数被当成现状引用,而新小节已经改对了**。

⟹ 新增/修改架构数时,顺手在 `tests/test_prose_numbers_match_the_code.py` 里
加一条:**从代码当场数出来,再断言文档里有这个数**。
判据要**窄**(只钉"改代码就必须同步改文档"的那几个),别钉每加一条测试就会变的量 ——
那种会退化成噪声,让人习惯性忽略红。

⚠️ 写这种守卫时先 `grep` 一遍**那个数到底写在哪份文档里**:
本次第一版扫 `开发者文档.md` 找指标总数,而它**根本没写**,于是红的是测试不是代码。

### B-16 测试里显式传的参数,盖住了默认值 —— 而生产用的是默认值

同一夜,`createAnalysisHealth(report, threshold = 5)` 的三条单元测试**全都显式传了
第三个参数**(`3` / `2` / `2`)。把默认值改成 `9999` 再跑 ⟹ **16 条全绿**。
而生产里两个页面调的都是 `createAnalysisHealth(recording.addDegraded)` ——
**一个参数都不传**,用的正是那个默认值。

⟹ 给带默认值的函数写测试时,**至少留一条不传那个参数的**。否则你测的是
"显式传 3 时行为对不对",而线上跑的是 5。

### B-17 判据落在"源码里有这串字"上,而不是"这段代码被接上了"

同一夜,两个页面的守卫只断言源码里出现 `createAnalysisHealth` 与 `addDegraded`
两串。把两处 `analysisHealthRef.current.fail(...)` **删掉**、把对象换成空壳
`(() => ({fail(){}, ok(){}}))()` ⟹ **照旧全绿**。两串都还在。

⟹ 检查"接线"时,判据要落在**调用点**上:把每个 `.catch(err => {...})` 段切出来,
断言这一段里**真的调了**那个函数。与本仓记过的「恒真断言」是孪生形态 ——
区别是恒真断言恒真,这一种是**判据太松**,松到变异穿过它。

## C. 外壳脚本(重试 + 到点停)

> 放在 `tools/jx_night_run.sh`。**未提交进仓库前先在本机验证一遍语法**。
> 核心是两件事:**403 重试** 和 **到点停**。

```bash
#!/usr/bin/env bash
# JingXin 夜跑外壳:到点停 + 配额重试 + 日志留痕。
#
# 用法:
#   tools/jx_night_run.sh [结束时刻,默认 06:00] [最大重试次数,默认 3]
#
# 注意:
#   * 用 --resume 续上下文,重试不丢进度。
#   * 每轮结束都会把结果追加到 logs/night_run_<日期>.log。
#   * 这个脚本**不做任何 git 操作** —— 提交/推送由会话内自己按 A 节收口动作做。
set -uo pipefail

STOP_AT="${1:-06:00}"
MAX_RETRY="${2:-3}"
LOG_DIR="${JX_LOG_DIR:-$HOME/jingxin/logs}"
PROMPT_FILE="${JX_PROMPT_FILE:-$HOME/jingxin/docs/夜跑提示词.md}"
mkdir -p "$LOG_DIR"

# 从提示词文档里抽出 A 节(两个 ``` 之间)作为实际提示词。
PROMPT="$(awk '/^```$/{n++; next} n==1' "$PROMPT_FILE")"
if [ -z "$PROMPT" ]; then
  echo "❌ 没从 $PROMPT_FILE 抽出提示词(A 节应为第一个代码块)" >&2
  exit 1
fi

stamp() { date '+%Y-%m-%d %H:%M:%S'; }
LOG="$LOG_DIR/night_run_$(date +%Y%m%d).log"
say() { echo "[$(stamp)] $*" | tee -a "$LOG"; }

# 到点了吗?跨零点也算(例如现在是 23:40,结束是 06:00)。
past_stop() {
  local now stop
  now=$(date +%H%M)
  stop=$(echo "$STOP_AT" | tr -d ':')
  if [ "$stop" -lt 1200 ]; then          # 结束时刻在凌晨
    [ "$now" -ge "$stop" ] && [ "$now" -lt 1200 ]
  else                                    # 结束时刻在白天/晚上
    [ "$now" -ge "$stop" ]
  fi
}

say "夜跑开始,结束时刻 $STOP_AT,最多重试 $MAX_RETRY 次"
say "日志:$LOG"

attempt=0
SESSION_ARGS=()
while :; do
  if past_stop; then
    say "⏰ 已到 $STOP_AT,停止。"
    exit 0
  fi

  say "第 $((attempt + 1)) 轮启动${SESSION_ARGS[*]:+ (续上一次会话)}"
  out="$(claude --permission-mode auto \
                 "${SESSION_ARGS[@]}" \
                 -p "$PROMPT" 2>&1)"
  rc=$?
  printf '%s\n' "$out" | tee -a "$LOG"

  # 配额不足:等一会儿再续,不重开。
  if printf '%s' "$out" | grep -q 'Subscription quota is insufficient'; then
    attempt=$((attempt + 1))
    if [ "$attempt" -ge "$MAX_RETRY" ]; then
      say "❌ 配额重试 $MAX_RETRY 次仍失败,退出。"
      exit 2
    fi
    wait_min=$((attempt * 10))
    say "⚠️ 配额不足,${wait_min} 分钟后重试(第 $attempt 次)。"
    sleep $((wait_min * 60))
    SESSION_ARGS=(-c)          # 续上最近一次会话,不丢上下文
    continue
  fi

  if [ "$rc" -eq 0 ]; then
    say "✅ 本轮正常结束(rc=0)。"
    exit 0
  fi

  # 其他错误:不盲目重试,留痕退出让人看。
  say "❌ 异常退出 rc=$rc,见日志。"
  exit "$rc"
done
```

### 用之前必须确认的三件事

1. **`-p` 模式会跳过工作区信任对话框** —— 只在**你信任的目录**里跑。
2. **`--permission-mode auto` 仍会拦危险动作**(强推、删远程分支、改权限、
   往生产机写)。想完全放开才用 `bypassPermissions`,但那不该无人值守跑。
3. **`-c` 续的是"最近一次会话"** —— 如果你在这期间开了别的会话,它会续错。
   更稳的做法是记下 session id 用 `--resume <id>`。

### 建议加一层:到点后强制收口

脚本只负责「不无限跑」。**收口动作(提交/推 git)必须由会话内自己做** ——
因为只有它知道这轮改了什么、门过没过。所以提示词 A 节里那句
「到早上 6 点 … 收口」是**承重的**,删了它,到点停就只是停,状态没保存。
