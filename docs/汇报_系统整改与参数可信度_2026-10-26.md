# JingXin 多模态行为观测系统
## 整改流程、算法与参数可信度汇报

**日期**：2026-10-26　**对象**：乙方汇报　**范围**：当前生产路径（L1 指标层 + 报告/导出 + 采集端）

---

## 0. 先给结论与边界

### 0.1 系统是什么

JingXin 采集一场面试/科研评估中的**面部动作单元（AU）、手部与体态、语音韵律、话语文本**，
把原始记录落成逐帧/逐回答的 CSV 与整场录像，再由报告层按**有出处的判据**披露：
「哪些行为线索有证据、证据有多强、哪些没有」。

### 0.2 系统**不是**什么（三条硬边界，来自项目既有裁定）

1. **不产出对个人的评分、评级、心理结论。** 没有标定样本，不同量纲不能折算成同一尺度 ——
   报告里不出现"综合分」和"五档评语"。
2. **阈值只能来自物理下限或自采数据。** 上游数据集的许可禁止把在其分布上拟合的参数用于
   真实招聘/筛选/心理画像；**在数据集分布上拟合的参数同样属禁**。
3. **算不出来就说算不出来。** 每条指标必须带 `n_valid / n_total / confidence / gap`；
   缺数据、缺标定、缺产出方，各自报不同的 `gap`，**不许用别的东西顶替**。

> 因此本稿回答的不是"这套系统有多准"，而是**"每个数是怎么算出来的、能信到什么程度、
> 哪些数我们拒绝给"**。

## 1. 系统构成与数据流

```
浏览器（采集端）
  ├─ 摄像头/麦克风（1280×720，VP8+Opus）
  ├─ 设备自检：面部 + 手部 + 麦克风都通过才允许开始（探针不落盘）
  ├─ 原生录像 camera.webm（整场）
  ├─ 逐帧：face/gesture 各一份原始 jpg（约 1 帧/秒）
  └─ 逐题音频 + 逐题作答

三个分析服务
  ├─ :8000 face_expression    AU / iris / 头姿 / 眨眼
  ├─ :8002 gesture_analysis   手部/姿态 landmark、抖动、角度
  └─ :8001 voice_interaction  FunASR 转写 + 韵律（pyin/rms）
        │
        ├─ data/logs/face_au_log_<sid>.csv          （逐帧 92 列）
        ├─ data/logs/gesture_emotion_log_<sid>.csv  （逐帧 59 列）
        ├─ data/logs/{interview,research}_emotion_log_<sid>.csv（逐题 32 列）
        └─ recordings/<场>/media/                    camera.webm / face/ / gesture/ / audio/
            recordings/<场>/                         transcript.json / questions.jsonl / label.json
                                                     retention.*.jsonl（留存账本）/ session.json

报告/导出层
  ├─ 回答窗口（questions.jsonl 的 ask_end 切窗）
  ├─ L1 指标层（38 条：F 16 + G 7 + V 12 + T 3）
  ├─ 质量门（样本门槛 → 置信度 4 档 / 9 类 gap）
  ├─ 维度映射（14 个旧槽 → 8 换 / 6 删；不给维度分）
  ├─ 交付物：HTML 报告（含身份/测试时间/生成时间）、结构化报告 API
  ├─ 数据导出：原始 CSV / 转写 TXT-CSV-JSON / 按模块动态图表
  └─ 题库：多套 + 当前生效 + 参考答案（只存不用）
```

服务端口：前端 `:5173`、面板 `:5000`、face `:8000`、voice `:8001`、gesture `:8002`、
FunASR `:10095`。远程访问走 Tailscale：
`https://gpuserver.tail4ffce2.ts.net:5173`。

## 2. 整改流程（问题 → 动作 → 验证）

> 原则：**不是"让它多出分"，而是"别让它说不成立的话"**。下面每一条都能在仓库里
> 找到对应的测试或实测记录。

### 2.1 素材留存与可追溯（M2.6）

| 问题 | 动作 | 验证 |
|---|---|---|
| 原始素材不可再生，分析代码必然有缺陷 | 整场 `camera.webm` 原样留存；逐帧/逐段原始字节留存；每次留存写 `retention.*.jsonl`（bytes + sha256 + 来源端点） | 账本逐条可对；`tests/test_media_retention*` |
| 同一场二次上传会**覆盖**上一份（2026-09-28 实盘丢 2.1 GB） | `camera.webm` 已存在时**拒绝覆盖**（HTTP 409），要求开新的一场 | `CameraAlreadyRetained` + 端点 409 |
| 上传了但文件里没有视频/音轨、或全黑 | 落盘后立刻做**录制体检**：视频轨/音轨/音视时长比/抽帧亮度；结果写 `session.json.capture_health` | 体检只报告不阻塞；`capture_health.py` |
| 上传失败被显示成"任务完成" | 留存端点返回 `stored: false`，前端据此报错，不许静默 | 端点契约 + 前端保存门禁 |

### 2.2 从"模糊匹配"到 L1 指标层（M4）

**问题**：旧引擎用列名子串从扁平特征里模糊匹配 14 个槽 —— 历史上把「皱眉」匹配到
从 `micro_exp` 字符串解析出的垃圾，同一场报告给出两套互相矛盾的数。

**动作**：
- 建立 **L1 指标层**：38 条指标，每条固定字段
  `name / family / formula / required_l0 / window / value / unit / n_valid / n_total / confidence / gap`；
- 三条不变量：`gap` 非空 ⟹ 值为 NaN 且置信度"无"；`n_valid ≤ n_total`；置信度只用四个中文词；
- **删掉"折算→加权→维度分→复合分"整条链**：没有标定样本就不折算；
- 槽位逐条对账：14 个旧槽 **8 条换成同构念 L1、6 条删**（删的写明"没有同构念"，不拿相邻构念顶替）。

**验证**：`tests/test_m4_*`、`tests/test_l1_*`；报告覆盖数 8/14（示例场）与结构化 API 逐字一致。

### 2.3 报告口径统一

**问题**：前端报告页读 L1，HTML 报告还在旧引擎 —— 同一场一个说 7/14、一个说 11/14。

**动作**：HTML 报告与 `/api/report/structured` 统一走 `build_l1_report`；旧引擎只留
`?engine=legacy` 做对照；报告正文只印"这一场量到了什么"，消失的维度单独列出并写明
"当前管线不测"。

**验证**：`tests/test_html_report_uses_the_l1_engine.py`。

### 2.4 报告可读性与身份

- 报告头：被测者 / 学号 / 院系 / 场次；**测试时间**（会话 id 的铸号时刻）与**报告生成时间**分开印；
- 文件名带姓名（`Research_Assessment_Report_<生成时刻>-候选Y.html`），列表同步显示；
- 报告列表：`科研评估报告 · 候选Y` + 完整文件名；
- 生成报告按钮的状态判断修正（服务端状态是 `success/error`，此前前端等的是
  `completed/failed`，导致永远"正在生成…"）；
- 不新增评分/档位。

### 2.5 采集防呆（2026-10-26）

**问题**：离摄像头太远时，人脸检出率与 AU 精度下降，而系统照常开录（事后只能对着空日志）。

**动作**：开录前（征询确定后、**铸号之前**）做设备自检：
- 面部检出且 `face_scale ≥ 0.20`（正常坐姿实测 0.25–0.47）；
- 至少一只手进入画面（左右分别显示）；
- 麦克风有可用音轨；
- 三条全过才允许点「开始面试」；取消则**不铸号**，盘上什么都不留；
- 探针走 `?probe=1`：只检测，**不落帧、不写 CSV、不落取景决策**。

**验证**：真实留存帧探针（face_scale 0.31–0.47、双手检出）；前端端到端（模拟摄像头 +
模拟探针）：就绪→按钮可用，取消→场次数量不变。

### 2.6 题库与数据导出（2026-10-26）

- 题库：每个模块可存**多套**，选一套"当前生效"；上传 JSON/CSV；参考答案可选（只存不用，
  留给后续比对/评分）；语音服务在**新开一场**时读取，切换下一场生效。
- 数据导出：三份原始 CSV、转写 TXT/CSV/JSON（含姓名）、按模块图表。
- 图表：从 CSV 列**动态**取数（面部 14 个 AU、10 项其他指标；手势 10 个手指角度、6 个关节角度、
  10 项稳定性指标；语音 6 个分面），不硬编码三个 AU。

### 2.7 运维加固

- 面板 `debug=False`（改之前 debug reloader 一天重启 42 次，内存里的任务表被清空，
  前端永远"正在生成…"）；
- CORS 白名单按访问来源配置；服务 `setsid` 启动，脱离终端；
- 上传端超时设为 0（大文件不允许 30 秒掐断）；错误响应区分 400/409/413/500。

## 3. 算法与计算过程

### 3.1 采集与时间轴

| 项 | 取值/做法 |
|---|---|
| 视频 | 浏览器 MediaRecorder，1280×720，VP8 + Opus；整场一个 `camera.webm` |
| 抽帧 | 采集端 5 fps 取帧、每 5 帧送 1 帧 ⟹ **约 1 帧/秒**；原始帧逐张留存 |
| 服务端时间 | 时间戳由**服务端实测**，忽略客户端申报的 fps；墙钟异常场次做 clock repair 并标记 |
| 回答窗口 | 窗口 k = `[ask_end_k, ask_end_{k+1})`，来自 `questions.jsonl` 的提问台账；**用 ask_end 而不是 ask_start**（提问那段是机器在说话，不是受试者行为） |
| 无台账场次 | 退化为一个 `session` 窗口，并明写原因（不编窗口） |

### 3.2 面部（F 族，16 条）

**输入**：MediaPipe FaceMesh 关键点 + 52 维 blendshape + iris。
日志 92 列，其中 14 个 AU、52 个 blendshape、视线/头姿/眼开度/对称度等。

**AU 的算法（几何比，不是"表情分类"）**：

- 每条 AU = 两个关键点距离 ÷ 一个解剖尺度，**无量纲**；
- 例：`au4_frown` = 双眉内侧点距 ÷ 眼距 —— **越小越皱**（旧公式方向曾经写反，已修）；
- 例：`au6_cheek_raise` 分母用**面部轮廓高**（前额顶→下巴），因为眼距是横向跨度、会把头偏航带进结果；
- 例：`au12_smile` 由嘴角/口宽等关键点几何比派生；`face_scale` = 面部轮廓高，作为**协变量**显式输出（不是"表情强度"）；
- 眨眼：`is_blink = EAR < 阈值` 是逐帧电平；**次数用 0→1 上升沿计数**，不是对帧求和。

**16 条指标**（`l1_face.py`）：

| 指标 | 公式（简） | 阈值策略 | 当前能否出数 |
|---|---|---|---|
| `smile_ratio` | `au12 > 0.263` 帧占比 | 声明常量 0.263（语料 p75，**非标定**） | 9 条"需 τ"中之一 |
| `smile_rate_per_min` | 穿越 0.263 的上升沿 ÷ 分钟 | 同上 | 同上 |
| `smile_duration_p50` | 连续超阈段时长的中位数 | 同上 | 同上 |
| `gaze_aversion_ratio_vs_baseline` | \|gaze\| > 本人中位数+3·MAD 帧占比 | 自比基线 | 同上 |
| `gaze_aversion_rate_per_min_vs_baseline` | 偏离→回正次数 ÷ 分钟 | 自比基线 | 同上 |
| `head_away_ratio_vs_baseline` | \|head_yaw\| > 本人中位数+3·MAD 帧占比 | 自比基线 | 同上 |
| `brow_furrow_ratio_vs_baseline` | `au4 < 本人中位数−3·MAD` 帧占比 | 自比基线 | 同上 |
| `lip_compression_ratio_vs_baseline` | `au23 < 本人中位数−3·MAD` 帧占比 | 自比基线 | 同上 |
| `au_activation_any_ratio` | 至少一条可信 AU 超本人 τ 的帧占比 | 5 条自比 + 1 条声明 | 同上 |
| `gaze_stability` | `1 − std(gaze_x) / 极差` | 无需 τ | ✅ |
| `blink_rate_per_min` | 上升沿数 ÷ 有效分钟 | 无需 τ | ✅ |
| `blink_duration_mean` | 眨眼段时长均值 | 无需 τ | ✅ |
| `head_motion_per_sec` | 头姿角速度绝对值和 ÷ 有效秒 | 无需 τ | ✅ |
| `au_variability_per_sec` | AU 帧间变化绝对值和 ÷ 有效秒 | 无需 τ | ✅ |
| `micro_exp_rate_per_min` | 微表情事件率 | — | ❌ 四列实测 0 非空 |
| `micro_exp_duration_mean_sec` | 微表情时长 | — | ❌ 同上 |

> 结论：F 族 16 条里 **5 条可出数、9 条卡"需标定阈值"、2 条结构性不采集**。
> "卡标定"的 9 条报 `gap="uncalibrated"`，**不给值**——不拿视频内分位顶替。

### 3.3 手势与体态（G 族，4 + 3 协变量）

**输入**：MediaPipe Hands/Pose landmark；日志 59 列。

**要点**：

- `jitter` 在写入端**已经按秒、且除以肩宽中位数**归一（`_calculate_jitter(divide_by_shoulder=True)`）——
  L1 不再乘除任何东西，再除一次会把取景远近的影响平方掉；
- 手部指标（fist/spread/指节角度）实测样本很少（49 场里只有 4/236、2/236 行有值），**基本不可用**；
- `is_valid` 恒为 False（49 场每行都是），它代表"手势情绪推断有没有有效输入"，**不代表有没有姿态数据**；
- `hand_visible_*` 的空串不是 0（"不知道" vs "确定没有"），所以可见率只能算**下界**。

| 指标 | 公式 | 单位 | 状态 |
|---|---|---|---|
| `gesture_activity_per_sec` | Σ(腕/肘/肩 jitter) 逐帧均值 | 归一化/秒 | ✅ |
| `posture_stability` | Σ(躯干/肩 jitter) 逐帧均值（越小越稳） | 归一化/秒 | ✅ |
| `pose_valid_ratio` | 躯干/肩/肩宽四列同时非空的帧占比 | 占比 | ✅（协变量） |
| `hand_visible_ratio_l/r` | `hand_visible_* == 1` 帧占比 | 占比（**下界**） | ✅ |
| `gesture_burst_rate_per_min_vs_baseline` | 超本人基线（中位数+3·MAD）的连续段（≥2 s）次数 ÷ 分钟 | 次/分 | ⚠️ 需自比基线 |
| `postural_shift_rate_per_min_vs_baseline` | `torso_jitter` 超本人基线的连续段次数 ÷ 分钟 | 次/分 | ⚠️ 需自比基线 |

> 2 秒下限不是标定值，是**1 Hz 采样率的下限推论**：单帧超基线无法与检测抖动区分。

### 3.4 语音与文本（V 族 12 条 + T 族 3 条）

**转写**：FunASR（paraformer 在线/离线 + VAD + 标点），逐题音频 → `transcript.json`；
音频为**全场混音（面试官 + 受试者）**，没有说话人分离。

**韵律**：librosa `pyin` 逐帧 `f0 / voiced_prob`，`rms` 逐帧；停顿 = `f0` 非有限 ≥ 0.2 s；
聚合成每段回答的 32 列（pitch/energy/pause/duration/chars 等）。

**V 族 12 条**：

| 指标 | 算法 | 单位 | 状态 |
|---|---|---|---|
| `speech_rate` | 字数 ÷ 有声秒 | 字/秒 | ✅（**全场混音**，不是"考生语速"） |
| `pause_rate_per_min` | 停顿次数 ÷ 语音分钟 | 次/分 | ✅ |
| `pause_ratio` | (总时长−有声) ÷ 有声 | 占比 | ⛔ 与 `1/voiced_ratio−1` 恒等（r=0.999），**故意不产出** |
| `response_latency_sec` | `ask_end` → 首次开口 | 秒 | ✅ 需提问台账；无台账报 `window_none` |
| `voiced_ratio` | 浊音帧占比（序列重算） | 占比 | ✅ 需先跑序列提取 |
| `pause_duration_p50` / `p90` | 停顿区间分位（序列） | 秒 | ✅ 需序列 |
| `pitch_median` | 浊音帧 f0 中位数 | Hz | ✅ 需序列 |
| `pitch_range_semitone` | 首末半音差 | 半音 | ✅ 需序列 |
| `pitch_variability_per_sec` | 逐帧半音差绝对值和 ÷ 浊音秒 | 半音/秒 | ✅ 需序列 |
| `energy_median` | rms 中位数 | — | ✅ 需序列（**跨设备不可比**，见 G4 封停） |
| `energy_dynamics_per_sec` | 逐帧 rms 差绝对值和 ÷ 浊音秒 | — | ✅ 需序列 |

> 8 条"序列指标"缺的是**序列没落盘**，不是缺数据 —— 用 `voice_series.py` 从原始音频重算；
> 必须显式跑过提取，否则报 `not_extracted`，不拿聚合量硬凑同名指标。

**T 族 3 条**（分母是**字**，不掺时长）：

- `lexical_diversity` = 二元组 MATTR（窗口 100）—— 原始 TTR 随文本变长单调下降，是长度伪影；
- `discourse_marker_rate` = 连接词**出现次数** ÷ 汉字数 × 100；
- `self_repair_rate` = 自我修正标记次数 ÷ 汉字数 × 100。

> ⚠️ 三条都是**全场混音**量，不是"受试者一个人的话语"。这条限制写进每条的公式串。

### 3.5 质量门与置信度（G3）

**样本门槛**（`evidence_thresholds.json`，临时值，M5 标定后替换）：

| 族 | 门槛 | 单位 |
|---|---|---|
| blink | 20 | frame |
| gaze | 30 | frame |
| au | 30 | frame |
| head_pose | 30 | frame |
| pause | 2 | answer |
| pitch | 5 | answer |
| energy | 5 | answer |
| speech | 2 | answer |
| density | 5 | answer |
| n_chars | 5 | answer |
| reaction_time | 5 | answer |

**置信度四档**（`confidence_for`）：

- `无`：一条有效观测都没有；
- `低`：有观测，但不到该族门槛；
- `中`：过门槛，但不到"两倍门槛且覆盖率 ≥ 80%"；
- `高`：`n_valid ≥ 2 × 门槛` **且** `n_valid / n_total ≥ 0.8`。

**报告级**：

- 每条指标带 `confidence` 与 `gap`；
- 维度置信度 = 该维**最弱**的那条证据（不可能比最弱的更强）；
- `confidence_cap` = 通过证据门的槽里**最乐观**的那一档（报告头"置信度上限"）；
- 覆盖率 = 通过证据门的槽数 / 全部 14 个旧槽（含已删槽）；删槽在报告里显式列出。

**9 类 gap**（每类对应不同补救动作）：
`uncalibrated`（缺标定）、`column_empty`（列全空）、`modality_missing`（整场没这个模态）、
`time_unusable`（时间轴不可重建）、`window_none`（没有可用回答窗口）、`no_samples`（窗口内无观测）、
`not_stored`（只存了聚合量）、`not_extracted`（素材在、序列没生成）、`not_produced`（本层故意不产出）。

### 3.6 维度映射（14 个旧槽）

| 维度 | 旧槽 → L1 | 死权重 |
|---|---|---|
| 话语结构特征 | 连接词密度→`discourse_marker_rate`；视线标准差→`gaze_stability`；皱眉→`brow_furrow_ratio_vs_baseline` | 0 |
| 情境行为稳定性 | 唇压缩→`lip_compression_ratio_vs_baseline`；腕抖动→`gesture_activity_per_sec`；**对称性→删** | 0.25 |
| 沟通表达流畅度 | **流畅度→删（无产出方）**；语调→`pitch_variability_per_sec`；停顿→`pause_duration_p50` | 4/7 |
| 行为表现活跃度 | 手掌张开/耸肩/眼神接触 **三条全删** | 1.0（整维消失） |
| 作答过程特征 | **字数→删**；反应延迟→`response_latency_sec` | 0.4 |

> 只给"这一维有几条过了证据门"与"最弱证据的置信度"，**不给维度分、不给档位**。

## 4. 每个参数的可信度（逐项）

### 4.1 可信度分级（本稿口径）

| 级别 | 含义 | 处置 |
|---|---|---|
| **A · 可复核测量** | 公式可复核、用相对量/率、不依赖外部阈值；报告里带 n_valid 与置信度 | 可以看数值；置信度按样本量与覆盖率判 |
| **B · 需标定 / 自比基线** | 公式方向明确，但阈值 τ 只能来自标定集（M5 未到位） | 报 `uncalibrated`，**不给值**；只看方向与定义 |
| **C · 结构性不产出** | 没采集、无产出方、或与另一条恒等 | 报 `column_empty / not_produced / not_stored`，**不拿别的顶替** |

### 4.2 面部

| 指标 | 级别 | 计算 | 门槛 | 可信度与限制 |
|---|---|---|---|---|
| `gaze_stability` | A | `1 − std(gaze_x)/极差` | gaze 30 帧 | 只看本场内的相对稳定；取景/头偏航会进来 |
| `blink_rate_per_min` | A | 眨眼上升沿 ÷ 有效分钟 | blink 20 帧 | 依赖 EAR 阈值；1 Hz 采样会漏短眨眼 |
| `blink_duration_mean` | A | 眨眼段时长均值 | blink 20 帧 | 同上 |
| `head_motion_per_sec` | A | 头姿角速度绝对值和 ÷ 有效秒 | head_pose 30 帧 | 头姿由关键点解算，极端角度误差大 |
| `au_variability_per_sec` | A | AU 帧间变化绝对值和 ÷ 有效秒 | au 30 帧 | 只能同场比较；跨人基线不可比 |
| `smile_ratio` 等 3 条 | B | AU12 超 0.263 的占比/率/时长 | au 30 帧 | 0.263 是全语料 p75 的**声明常量，未标定** |
| `gaze_aversion_*` / `head_away_ratio` / `brow_furrow_ratio` / `lip_compression_ratio` / `au_activation_any_ratio` 共 6 条 | B | 自比本人基线（中位数 ± 3·MAD） | 见各条 | 方向明确、基线自比；**没有标定集，不给值** |
| `micro_exp_*` 2 条 | C | 微表情事件 | — | 四列实测 **0/1086 非空**；1 Hz 也不够（onset 40–200 ms） |

### 4.3 手势与体态

| 指标 | 级别 | 计算 | 门槛 | 可信度与限制 |
|---|---|---|---|---|
| `gesture_activity_per_sec` | A | Σ(腕/肘/肩 jitter) 逐帧均值 | 帧级默认 10 | jitter 已按秒、除以肩宽；只同场比较 |
| `posture_stability` | A | Σ(躯干/肩 jitter) 均值（越小越稳） | 帧级默认 10 | 同上 |
| `pose_valid_ratio` | A（协变量） | 躯干/肩/肩宽四列非空帧占比 | — | **不能**用 `is_valid`（恒 False） |
| `hand_visible_ratio_l/r` | A（**下界**） | `hand_visible_* == 1` 帧占比 | — | 空串 ≠ 0，所以只能当下界 |
| 2 条 burst 率 | B | 超本人基线（中位数+3·MAD）的连续段（≥2 s）÷ 分钟 | — | 2 s 是 1 Hz 的下限推论；无标定 |

> 手指角度/张开度/耸肩：日志里有列，但**样本极少**（手经常在画面外）⟹ 不进 L1 指标，
> 只在数据导出页原样展示（不作为行为结论）。

### 4.4 语音与文本

| 指标 | 级别 | 计算 | 门槛 | 可信度与限制 |
|---|---|---|---|---|
| `speech_rate` | A | 字数 ÷ 有声秒 | speech 2 段 | **全场混音**（含面试官）；不是"考生语速" |
| `pause_rate_per_min` | A | 停顿次数 ÷ 语音分钟 | pause 2 段 | 停顿定义 = f0 非有限 ≥0.2 s |
| `response_latency_sec` | A | `ask_end` → 首次开口 | reaction 5 段 | 需提问台账；墙钟不可信场次有误差 |
| `pause_ratio` | C | (总−有声)/有声 | — | 与 `1/voiced_ratio−1` 恒等（r=0.999），**故意不产出** |
| `voiced_ratio` / `pause_duration_p50/p90` / `pitch_median` / `pitch_range_semitone` / `pitch_variability_per_sec` / `energy_median` / `energy_dynamics_per_sec` | A（需序列） | 从原始音频逐帧重算 | pitch/energy 5 段 | 必须跑过 `voice_series` 提取；`energy_*` 跨设备不可比（G4 封停旧口径） |
| `lexical_diversity` | A | 二元组 MATTR（窗口 100） | density 5 段 | 中文二元组近似（无分词器）；全场混音 |
| `discourse_marker_rate` | A | 标记次数 ÷ 汉字 ×100 | density 5 段 | 与旧"几个不同标记"**口径不同**，历史数字不可直接比 |
| `self_repair_rate` | A | 自我修正次数 ÷ 汉字 ×100 | density 5 段 | 同上 |

### 4.5 协变量与不可用量

| 项 | 状态 | 说明 |
|---|---|---|
| `face_scale` | 协变量 | 脸高/画面高；用于设备自检（≥20%）与跨帧可比性，不当作"表情强度" |
| `series_available` | 协变量 | 本场是否有整场音频序列；没有时 V 族 8 条报 `not_extracted` |
| `emotion_state` / `tension` | 不产出 | 复合/加权别名，不是独立测量；旧报告已删 |
| `energy_mean`（日志聚合） | 封停 | 设备增益/距离代理，跨会话不可比 |
| `is_valid`（手势） | 不可用 | 49 场恒 False；用实际列非空判姿态数据 |
| `symmetry_score` / `eye_contact` / `n_chars` / `fluency_score` / `hand_spread` / `shrug` | 删槽 | 没有同构念 L1，不拿相邻量顶替 |

### 4.6 一条指标在报告里长什么样

```json

  "name": "blink_rate_per_min",
  "family": "F3_blink",
  "formula": "count_rising_edges(is_blink) / (valid_span_sec / 60)",
```

## 6. 已知限制与下一步

1. **标定集（M5）缺失**：所有"需 τ"指标保持 `uncalibrated`；阈值表是临时值（`_provisional`），
   替换即新模型版本。
2. **语音无说话人分离**：`speech_rate`、连接词密度、MATTR 都是**全场混音**；要做"考生语速"
   必须先做说话人分离（或只统计考生答题段）。
3. **采样率约 1 Hz**：微表情结构性不可用；眨眼/动作事件的漏检率高于 15–30 fps，报告已明示。
4. **手部可见性**：手经常在画面外，手指角度/张开度不进 L1；取景协议需继续统一。
5. **文本分析偏关键词**：连接词/自我修正表是人工列表；后续替换算法时，导出的 `Q/A CSV`
   与 `transcript.json` 就是现成输入。
6. **网络上传**：见 §7 的实测诊断（Tailscale 中继路径会显著拖慢 100–200 MB 的整场录像）。

## 7. 运维实测：上传为什么慢（2026-10-26）

- 实测客户端 `my-server (100.66.210.10)` 与服务器**没有建立直连**，`tailscale ping` 走
  **DERP 中继（tok）**，RTT 约 **1.06–1.27 秒**；
- 整场 `camera.webm` 约 150–180 MB；在该路径上实测约 **0.5 MB/s** ⟹ 一次上传 **5–6 分钟**；
- 服务器磁盘/内存/CPU 都不是瓶颈（面板与三个分析服务负载很低）；
- **结论：瓶颈在 Tailscale 中继链路，不在留存代码。**

可选的改进（按收益排序）：

1. **打通直连**：客户端路由器开 UPnP/NAT-PMP，或给两端任一开公网端口；`tailscale ping`
   显示 `direct` 后上传会显著变快；
2. **同局域网时走 LAN**：若客户端在 `192.168.72.0/24`，直接用 `http://192.168.72.30:5173`；
3. **降低录像码率**：VP8 720p 目前约 2.5–3 Mbps；改为 1.2–1.5 Mbps 可把上传时间减半
   （代价是画面细节，原始素材不可再生，需先确认）；
4. **上传进度提示**：当前保存门禁只有文字"正在上传"，没有百分比；可加 `onUploadProgress`，
   让等待可见（不改传输速度，只改感知）。

## 9. 一页话术（给汇报现场）

> "这套系统不给我们一个'分数'，它给的是一份**证据清单**：每个数都带公式、样本量和置信度；
> 算不出来的，它明确写'算不出来'以及为什么。我们这两轮整改做的是三件事：
> **① 把数据留下、可追溯；② 把每个指标的计算和可信度说清楚；③ 把采集端的坑（离太远、
> 手不在画面、题库只有一份）堵在开始之前。** 接下来要做的是标定集和说话人分离 ——
> 在它们到位之前，报告不会给出任何评分或评级。"
